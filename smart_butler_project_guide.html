專題實作・開發手冊

智慧管家系統

把長照監護、AI 對話與家電控制、家人留言板、智慧監視器整合成一套在 Windows 上運作的居家智慧管家；再加上用藥提醒、每日平安回報、一鍵求救、作息異常偵測，並讓系統能 24 小時穩定運作。全程搭配 Claude Code，一關一關按部就班完成。

適用高中職專題（3～4 人一組）
平台Windows 10／11＋Python
開發關卡L0～L15，共 16 關
建議時程16 週
AI 助手Claude Code

00怎麼使用這本手冊

這本手冊把整個系統拆成 16 個關卡。每一關都只做一件事，做完、測過、打勾，才進下一關。每一關都附上一段提示語，貼給 Claude Code，它會幫你寫程式；你的工作是看懂它做了什麼、實際測試、判斷對不對。

  1. ① 讀先讀本關的「目標」與「重點觀念」
  2. ② 貼複製提示語，貼到 Claude Code
  3. ③ 看讀它的回報與改了哪些檔案
  4. ④ 測照「檢核點」一項一項實際測試
  5. ⑤ 記打勾，並確認 PROGRESS.md 已更新

三個一定要遵守的習慣

  • 一次只做一關。不要把好幾關的提示語一起貼上。每一關做完都要先 git commit，出錯時才能退回。
  • 每關開頭都讀進度檔。L0 會建立 PROGRESS.md（做到哪裡）和 docs/專案規則.md（不能違反的規則）。之後每段提示語都會要求 Claude Code 先讀這兩份檔案，所以就算隔週開新對話，它也能接著做。
  • 它說「完成」不算數，你測過才算。每一關都要求它附上實際執行結果；你也要親手照檢核點再測一次。
已經有 Aina 系統的組別：請先用 07 共通提示語的「盤點既有專案」，讓 Claude Code 列出現有程式哪些可以沿用，再從 L0 開始把它們整理進新的架構。

01專題概要

背景與定位

台灣已進入超高齡社會，獨居或白天獨處的長輩越來越多。家人不在身邊時，最擔心的是：跌倒沒人知道、忘記吃藥、有陌生人來訪、身體不舒服卻聯絡不到人。市面上的產品多半各做一件事，彼此不相通。

本專題要做的是一套整合型的智慧管家：所有功能共用同一套設定、同一個紀錄資料庫、同一個通報管道（Discord），家人只要看一個頻道，就知道家裡的狀況。

專題目標

  1. 建立可擴充的平台：單一主程式、設定中心、事件紀錄、統一通報。
  2. 整合四大模組：長照監護、AI 對話與家電控制、留言板、智慧監視器。
  3. 加入四項照護功能：用藥提醒、每日平安回報、一鍵求救、作息異常偵測。
  4. 做到可以長時間運作：開機自動啟動、健康檢查、斷網備援、自動清除舊資料。
  5. 全程遵守隱私與安全規範，並能用數據說明系統表現。

02系統架構

所有模組都不直接互相呼叫，而是把發生的事情包成一個事件丟到事件匯流排。紀錄器負責存進資料庫，通報器負責依等級送到 Discord，管理介面負責顯示。這樣新增一個模組時，不需要改動其他模組。

資料夾結構（L0 會建立）

smart_butler/
├─ main.py                  主程式：啟動、監看、重啟各模組
├─ config/
│  └─ settings.yaml         所有可調參數（不放密碼）
├─ .env                     金鑰與 Webhook（絕不上傳）
├─ .env.example             .env 的範本（可以上傳）
├─ core/                    共用服務：設定、事件、紀錄、通報
├─ modules/                 每個功能一個資料夾
│  ├─ care/  chat/  board/  camera/
│  └─ meds/  daily/  sos/   routine/
├─ web/                     本機管理介面
├─ data/                    資料庫、截圖（自動清除）
├─ demo/                    示範影片與模擬資料
├─ tests/                   自動測試
├─ docs/專案規則.md          不能違反的規則
└─ PROGRESS.md              目前做到哪一關

  • USB 網路攝影機 1 支（長照監護、智慧監視器）。開發時一律先用示範影片，最後才接真實攝影機。
  • 麥克風、喇叭（AI 對話、用藥提醒語音）。
  • 可選：Wi-Fi 智慧插座 1～2 個（家電控制）；實體按鈕（一鍵求救，先用鍵盤模擬）。

  1. 在 #測試通報 頻道：頻道設定 → 整合 → Webhook → 新增，複製 Webhook 網址。
  2. 留言板雙向同步與「已處理」按鈕需要 Bot：到 Discord Developer Portal 建立應用程式與 Bot，複製 Bot Token，邀請進伺服器。

金鑰外洩怎麼辦：Webhook 網址或 Bot Token 只要被別人拿到，對方就能用你的身分發訊息。一旦不小心上傳或貼出，立刻到 Discord 刪除並重新產生。

L0專案骨架與規則

目標
建立資料夾結構、進度檔、專案規則檔，並用 Git 開始版本管理。
時間
約 1 節

重點觀念

  • 規則檔：把「不能做的事」寫成檔案，之後每一關都讓 AI 先讀，比每次重講更可靠。
  • 進度檔：AI 不會記得上週的對話，所以要把「做到哪裡、決定了什麼」寫下來。

提示語

請在目前資料夾建立「智慧管家系統」的專案骨架（Windows，Python 3.11）。

要建立的內容：
1. 資料夾：core/、modules/（底下 care、chat、board、camera、meds、daily、sos、routine 各一個空資料夾，各放 __init__.py）、web/、data/、demo/、tests/、docs/、config/
2. docs/專案規則.md，寫入以下規則（之後每一關都要遵守）：
   - 只修改本專案資料夾內的檔案
   - 金鑰、Token、Webhook 只放 .env，程式與設定檔不可出現明碼
   - 未經同意不可開啟攝影機或麥克風、不可發訊息到正式 Discord 頻道、不可控制真實家電；測試一律用 demo/ 的示範資料
   - 要安裝新套件、刪除檔案、變更資料庫結構前，先列出內容並等我同意
   - 相容 Windows：路徑用 pathlib，檔案一律 UTF-8，中文路徑要能正常運作
   - 影像、人臉、對話紀錄只存本機，要有保存天數
   - 每完成一項就更新 PROGRESS.md
3. PROGRESS.md：列出 L0～L15 共 16 關，標示目前完成 L0，並有「已做的決定」「已知問題」兩個段落
4. .gitignore：排除 .env、data/、__pycache__/、虛擬環境
5. README.md：一段專案簡介
6. 建立虛擬環境 .venv 的指令寫在 README（先不要安裝任何套件）
7. git init 並完成第一次 commit

完成後停下來，回報：建立了哪些檔案（用樹狀圖）、git log 的輸出。

L1設定中心與 .env

目標
所有可調參數集中在 settings.yaml，金鑰集中在 .env；程式用同一個函式讀取。
時間
約 1 節

重點觀念

  • 設定和程式分開：改門檻、改時間不需要改程式碼。
  • 啟動時就檢查設定：設定寫錯時，一開始就說清楚錯在哪，比跑到一半才當掉好找。

提示語

先讀 PROGRESS.md 與 docs/專案規則.md，並遵守規則。本關是 L1：設定中心。

L2事件匯流排與紀錄

目標
定義統一的事件格式；所有事件自動寫入 SQLite，可查詢、可匯出。
時間
約 2 節

重點觀念

  • 事件格式：每個事件至少有「時間、來源模組、類型、等級、內容、附件路徑」。格式統一，後面的通報、查詢、每日摘要才寫得出來。
  • 發布／訂閱：模組只負責發布事件，誰要處理就自己訂閱，模組之間互不依賴。

提示語

先讀 PROGRESS.md 與 docs/專案規則.md，並遵守規則。本關是 L2：事件匯流排與紀錄。

請完成：
1. core/events.py：
   - Event 資料類別：time（台北時間）、source、kind、level（info／warn／urgent）、message、attachment（可空）

2. core/store.py：用 SQLite（data/aina.db）儲存事件；提供 query(start, end, source=None, kind=None) 與 export_csv(path, start, end)
3. 啟動時自動把 EventBus 的事件寫入 store
4. tests/test_events.py：測試發布、訂閱、訂閱者出錯不影響其他人、依時間查詢、匯出 CSV

資料表結構先列給我看，等我同意再建立。
完成後執行測試並回報輸出，更新 PROGRESS.md，然後停下來。

常見卡關：CSV 在 Excel 變亂碼，是因為 Excel 需要 BOM。請它存成 utf-8-sig。

L3Discord 通報器與分級

目標
所有通報都經過同一個通報器；依等級決定格式與提醒方式；緊急事件會重送直到有人處理。
時間
約 2 節

重點觀念

  • Webhook 與 Bot 的差別：Webhook 只能「送出」訊息，簡單可靠；Bot 可以「讀取」與「按按鈕」，留言板同步和「已處理」需要它。
  • 重送與確認：緊急事件如果沒人看到，等於沒通報。所以要重送，直到有人確認。

提示語

先讀 PROGRESS.md 與 docs/專案規則.md，並遵守規則。本關是 L3：Discord 通報器。

請完成：
1. core/notify.py：訂閱 EventBus，依等級送到 Discord（Webhook 從 .env 的 DISCORD_WEBHOOK_TEST 讀取）
   - info：一般訊息
   - warn：訊息前加「⚠️ 注意」
   - urgent：訊息前加「🚨 緊急」並 @everyone，有附件時附上圖片
2. 緊急事件要能被確認：用 Discord Bot（Token 從 .env 讀取）在訊息下加「已處理」按鈕；沒人按的話每 5 分鐘重送一次，最多 6 次。重送間隔與次數寫在 settings.yaml
3. 送出失敗（例如斷網）時，先存進本機佇列 data/outbox，稍後自動補送（L14 會再強化）
4. 提供指令 python -m core.notify --test，依序送出三種等級的測試訊息到測試頻道
5. 測試時只能送到測試頻道

需要的套件（requests、discord.py）先列出來等我同意再安裝。
完成後回報：執行 --test 的輸出、Discord 上看到的結果要我確認；更新 PROGRESS.md，然後停下來。

檢核點

L4主程式與模組管理

目標
一個 main.py 啟動所有模組；模組可個別開關；某個模組當掉會自動重啟。
時間
約 2 節

重點觀念

  • 模組介面統一：每個模組都有 start()、stop()、health()，主程式才能用同一套方式管理。
  • 故障隔離：攝影機壞掉，不應該讓用藥提醒也跟著停。

提示語

先讀 PROGRESS.md 與 docs/專案規則.md，並遵守規則。本關是 L4：主程式與模組管理。

請完成：
1. core/module.py：定義模組基底類別，包含 name、start()、stop()、health()（回傳正常／異常與原因）
2. main.py：
   - 依 settings.yaml 的開關載入 modules/ 下的模組，每個模組在獨立的執行緒或行程執行
   - 每 30 秒檢查各模組的 health()；異常或當掉時自動重啟，並發出 warn 事件；同一模組 10 分鐘內重啟超過 3 次就停止重啟，改發 urgent 事件

09隱私、安全與倫理

這套系統會拍到人、聽到人說話，也會記錄長輩的生活作息。這些都是非常敏感的個人資料，做得不好會傷害你想照顧的人。

  • 知情同意：安裝前要讓長輩與同住家人了解系統會做什麼、並取得同意；門口攝影機要貼告示讓訪客知道。
  • 最少蒐集：只拍需要的區域，不拍浴室、臥室床上；能不存影像就不存，只存事件。
  • 只存本機、定期刪除：影像與對話不上傳雲端；設定保存天數並真的執行刪除。
  • 隱私模式：長輩要能自己按一下就暫停錄影，這是尊重，不是漏洞。
  • 人臉辨識：屬於高度敏感的生物特徵資料；沒有取得本人同意，不要建立人臉資料庫。
  • 系統不是醫療設備：它只能輔助，不能取代人的照顧與醫療判斷；報告與展示時要清楚說明。
  • 金鑰安全：Webhook、Token、API 金鑰只放 .env，外洩就立刻作廢重發。
  • 家電安全：會發熱或有危險的設備必須二次確認，並保留紀錄。

10常見問題

狀況可能原因與處理
終端機中文變亂碼Windows 終端機預設 Big5（cp950）。執行前設定 set PYTHONIOENCODING=utf-8，程式裡不要印出 ✗ 這類 cp950 沒有的符號。
專案路徑有中文就讀不到圖片或模型cv2.imread 不支援中文路徑，改用 np.fromfile＋cv2.imdecode；存檔用 cv2.imencode＋tofile。
Discord 沒收到訊息檢查 .env 的 Webhook 是否正確、是否有多餘空白；Bot 要先邀請進伺服器並開啟 Message Content Intent。
攝影機打不開確認沒有其他程式（視訊軟體）占用；換成 cv2.VideoCapture(0, cv2.CAP_DSHOW) 試試。
PowerShell 腳本中文亂碼或無法執行腳本要存成 UTF-8 with BOM；執行原則被擋時，用 powershell -ExecutionPolicy Bypass -File 腳本.ps1。
CSV 用 Excel 開是亂碼存成 utf-8-sig。
Claude Code 一次改太多提示語加上「只修改與本關直接相關的檔案」，並用 git 退回；每關做完就 commit。
隔週 Claude Code 不記得之前做過什麼正常現象。先用「接續上次的進度」提示語，並確認 PROGRESS.md 有更新。
