專題實作・開發手冊

智慧管家系統

把長照監護、AI 對話與家電控制、家人留言板、智慧監視器整合成一套在 Windows 上運作的居家智慧管家；再加上用藥提醒、每日平安回報、一鍵求救、作息異常偵測，並讓系統能 24 小時穩定運作。全程搭配 Claude Code，一關一關按部就班完成。

適用高中職專題（3～4 人一組）
平台Windows 10／11＋Python
開發關卡L0～L15＋延伸 L16～L19
建議時程16 週
AI 助手Claude Code／Antigravity

00怎麼使用這本手冊

這本手冊把整個系統拆成 16 個關卡。每一關都只做一件事，做完、測過、打勾，才進下一關。每一關都附上一段提示語，貼給 Claude Code，它會幫你寫程式；你的工作是看懂它做了什麼、實際測試、判斷對不對。

  1. ① 讀先讀本關的「目標」與「重點觀念」
  2. ② 貼複製提示語，貼到 Claude Code
  3. ③ 看讀它的回報與改了哪些檔案
  4. ④ 測照「檢核點」一項一項實際測試
  5. ⑤ 記打勾，並確認 PROGRESS.md 已更新

三個一定要遵守的習慣

  • 一次只做一關。不要把好幾關的提示語一起貼上。每一關做完都要先 git commit，出錯時才能退回。
  • 每關開頭都讀進度檔。L0 會建立 PROGRESS.md（做到哪裡）和 docs/專案規則.md（不能違反的規則）。之後每段提示語都會要求 Claude Code 先讀這兩份檔案，所以就算隔週開新對話，它也能接著做。
  • 它說「完成」不算數，你測過才算。每一關都要求它附上實際執行結果；你也要親手照檢核點再測一次。
已經有 Aina 系統的組別：可以用 07 的「整合版提示語」一次規劃整個升級（附逐段說明）；想一步一步學的，就先用「盤點既有專案」，再從 L0 開始把現有程式整理進新的架構。

使用 Antigravity 開發時的注意要點

本手冊以 Claude Code 為例，但提示語描述的是「要做什麼、不能做什麼、做到什麼程度才算完成」，Google Antigravity 等其他能讀檔、改檔、執行指令的 AI 開發工具也能使用。改用 Antigravity 時，請注意下面幾點：

項目注意要點
先出計畫再執行請它先產生任務清單或實作計畫給你審核，同意後才開始改程式。這就是本手冊「每關停下來回報」的做法。
自主程度把「執行終端機指令」設成需要審核，不要設成全自動。安裝套件、刪除檔案、開啟攝影機或麥克風前，都必須經過你同意。
一個對話只做一關每一關開一個新的對話；開頭一樣請它先讀 PROGRESS.md 與 docs/專案規則.md。
善用內建瀏覽器L9 管理介面可以請它用內建瀏覽器，以 375px（手機）和 1440px（電腦）寬度檢查版面，並附上截圖。
模型差異不同模型對同一段提示語的反應會有差異。第一關要特別確認它有沒有遵守規則檔；沒遵守就明確指出，並請它重讀規則。
進度檔一樣適用PROGRESS.md、docs/專案規則.md 是普通檔案，換工具也能接續。同一個專案可以前幾關用 Claude Code、後面改用 Antigravity。
金鑰安全不要把 Webhook、Token、API 金鑰貼進對話框；一律放 .env，請它從 .env 讀取。

使用 Antigravity 時，把下面這段貼在每一關提示語的最前面：

請先不要修改任何檔案。
先讀 PROGRESS.md 與 docs/專案規則.md，再根據下面的關卡內容，產生一份實作計畫給我審核：要建立或修改哪些檔案、需要安裝哪些套件、要執行哪些指令、怎麼測試。
我同意計畫後才開始執行；執行終端機指令、安裝套件、刪除檔案前都要再經過我同意。
完成後附上測試指令與實際輸出，並更新 PROGRESS.md。

（以下貼上本關的提示語）

Antigravity 版本更新很快，實際的按鈕名稱與設定位置，請以你電腦上的版本為準。

01專題概要

背景與定位

台灣已進入超高齡社會，獨居或白天獨處的長輩越來越多。家人不在身邊時，最擔心的是：跌倒沒人知道、忘記吃藥、有陌生人來訪、身體不舒服卻聯絡不到人。市面上的產品多半各做一件事，彼此不相通。

本專題要做的是一套整合型的智慧管家：所有功能共用同一套設定、同一個紀錄資料庫、同一個通報管道（Discord），家人只要看一個頻道，就知道家裡的狀況。

專題目標

  1. 建立可擴充的平台：單一主程式、設定中心、事件紀錄、統一通報。
  2. 整合四大模組：長照監護、AI 對話與家電控制、留言板、智慧監視器。
  3. 加入四項照護功能：用藥提醒、每日平安回報、一鍵求救、作息異常偵測。
  4. 做到可以長時間運作：開機自動啟動、健康檢查、斷網備援、自動清除舊資料。
  5. 全程遵守隱私與安全規範，並能用數據說明系統表現。

所有模組都不直接互相呼叫，而是把發生的事情包成一個事件丟到事件匯流排。紀錄器負責存進資料庫，通報器負責依等級送到 Discord，管理介面負責顯示。這樣新增一個模組時，不需要改動其他模組。

L0專案骨架與規則

目標
建立資料夾結構、進度檔、專案規則檔，並用 Git 開始版本管理。
時間
約 1 節

重點觀念

  • 規則檔：把「不能做的事」寫成檔案，之後每一關都讓 AI 先讀，比每次重講更可靠。
  • 進度檔：AI 不會記得上週的對話，所以要把「做到哪裡、決定了什麼」寫下來。

提示語

請在目前資料夾建立「智慧管家系統」的專案骨架（Windows，Python 3.11）。

要建立的內容：
1. 資料夾：core/、modules/（底下 care、chat、board、camera、meds、daily、sos、routine 各一個空資料夾，各放 __init__.py）、web/、data/、demo/、tests/、docs/、config/
2. docs/專案規則.md，寫入以下規則（之後每一關都要遵守）：
   - 只修改本專案資料夾內的檔案
   - 金鑰、Token、Webhook 只放 .env，程式與設定檔不可出現明碼
   - 未經同意不可開啟攝影機或麥克風、不可發訊息到正式 Discord 頻道、不可控制真實家電；測試一律用 demo/ 的示範資料
   - 要安裝新套件、刪除檔案、變更資料庫結構前，先列出內容並等我同意
   - 相容 Windows：路徑用 pathlib，檔案一律 UTF-8，中文路徑要能正常運作
   - 影像、人臉、對話紀錄只存本機，要有保存天數
   - 每完成一項就更新 PROGRESS.md
3. PROGRESS.md：列出 L0～L15 共 16 關，標示目前完成 L0，並有「已做的決定」「已知問題」兩個段落
4. .gitignore：排除 .env、data/、__pycache__/、虛擬環境
5. README.md：一段專案簡介
6. 建立虛擬環境 .venv 的指令寫在 README（先不要安裝任何套件）
7. git init 並完成第一次 commit

完成後停下來，回報：建立了哪些檔案（用樹狀圖）、git log 的輸出。

L1設定中心與 .env

目標
所有可調參數集中在 settings.yaml，金鑰集中在 .env；程式用同一個函式讀取。
時間
約 1 節

重點觀念

  • 設定和程式分開：改門檻、改時間不需要改程式碼。
  • 啟動時就檢查設定：設定寫錯時，一開始就說清楚錯在哪，比跑到一半才當掉好找。

提示語

先讀 PROGRESS.md 與 docs/專案規則.md，並遵守規則。本關是 L1：設定中心。

請完成：
1. config/settings.yaml：包含各模組開關（care、chat、board、camera、meds、daily、sos、routine）、Discord 頻道對應（用名稱，不放網址）、通報門檻、攝影機來源（預設為 demo/ 的示範影片）、資料保存天數（預設 30）、時區 Asia/Taipei。每個參數旁邊用中文註解說明用途
2. .env.example：列出需要的變數名稱（DISCORD_WEBHOOK_TEST、DISCORD_BOT_TOKEN、AI_API_KEY），值留空
3. core/config.py：讀取 settings.yaml 與 .env，提供 get_settings() 與 get_secret(name)；設定格式錯誤或缺少必要欄位時，印出中文錯誤訊息並指出是哪個欄位
4. tests/test_config.py：測試正常讀取、缺欄位、格式錯誤三種情況

需要的套件（PyYAML、python-dotenv、pytest）先列出來等我同意再安裝。
完成後執行測試，回報測試輸出，更新 PROGRESS.md，然後停下來。

L2事件匯流排與紀錄

目標
定義統一的事件格式；所有事件自動寫入 SQLite，可查詢、可匯出。
時間
約 2 節

重點觀念

  • 事件格式：每個事件至少有「時間、來源模組、類型、等級、內容、附件路徑」。格式統一，後面的通報、查詢、每日摘要才寫得出來。

提示語

先讀 PROGRESS.md 與 docs/專案規則.md，並遵守規則。本關是 L2：事件匯流排與紀錄。

L17防詐提醒

目標
長輩和管家對話時，若出現詐騙常見說法，立刻提醒並建議撥 165，同時通知家人。
時間
約 3～4 節

重點觀念

  • 組合判斷，降低誤報：只說「今天去 ATM 領錢買菜」不應該觸發。要「高風險詞」或「兩個以上的可疑詞同時出現」才提醒。
  • 它只是提醒，不是判定：系統不能確定是不是詐騙，所以用「很像詐騙，先問問看」的說法，並把判斷交給 165 與家人。
  • 只聽和管家的對話：管家不偷聽電話內容；只有長輩主動跟管家說的話才會被分析。

提示語

先讀 PROGRESS.md 與 docs/專案規則.md，並遵守規則。本關是 L17：防詐提醒（modules/antifraud/）。

背景：只分析長輩主動對管家（L6）說的話，不錄製、不監聽電話。

請完成：
1. settings.yaml 加入詐騙關鍵字，分成兩類：

   - 可疑詞（兩個以上同時出現才提醒）：ATM、匯款、轉帳、保證金、中獎、點數卡、加 LINE、檢察官、警察 等

整合版提示語逐段說明

一段好的提示語，每一段都有它的工作。了解每段在做什麼，之後你們就能自己改寫、加新功能。

段落在告訴 AI 什麼為什麼要這樣寫
任務標題一句話說明要做什麼、在哪個平台AI 讀到第一行就知道方向；標明 Windows，它才會注意路徑、編碼等 Windows 特有問題。
目標最後要得到什麼，以及「分階段、每階段停下來」先說結果，AI 才能判斷哪些工作有必要；「停下來等確認」是整份提示語最重要的安全機制。
現況專案在哪裡、已經有哪些功能、試過什麼失敗了AI 不知道你電腦裡有什麼。說清楚現況，它才會「在既有程式上改」，而不是從頭重寫；寫出失敗經驗，避免它重蹈覆轍。方括號要換成你們的實際內容。
範圍與限制能改哪裡、不能碰什麼；金鑰、隱私、測試的規則放在前面，是因為 AI 對開頭的內容最重視。這些是「做錯就很難挽回」的事（外洩金鑰、刪掉錄影、真的去開家電），所以寫成硬性規定。
階段 0：盤點先讀懂整個專案，用表格回報，不要改任何東西先確認 AI 看懂的和你們認知的一樣。如果盤點就錯了，後面全部會跟著錯；在這裡修正方向，成本最低。
階段 1：平台整合主程式、設定中心、事件、通報、管理介面先把共用的「地基」打好，之後每個新功能都只要發出事件；地基不穩，後面每加一個功能都要重改。
階段 2：照護功能4 項新功能，每項都要回報一次做 4 項，出錯時很難知道是哪一項造成的，所以要求逐項完成、逐項回報。
階段 3：系統穩定自動啟動、健康檢查、斷網備援、清除舊資料放在最後，因為這些是在「功能都正常」之後，確保系統能長時間運作的保險。
之後再做明確列出這次不要做的功能AI 常會「順手」多做很多功能，讓程式變複雜。寫出來並說只列在 README，範圍就被鎖住了。

行動界線哪些事可以直接做、哪些一定要先問讓 AI 在安全的範圍內自己工作，遇到有風險的事（刪檔、裝套件、開攝影機、建排程）就停下來問人。

09隱私、安全與倫理

這套系統會拍到人、聽到人說話，也會記錄長輩的生活作息。這些都是非常敏感的個人資料，做得不好會傷害你想照顧的人。

  • 知情同意：安裝前要讓長輩與同住家人了解系統會做什麼、並取得同意；門口攝影機要貼告示讓訪客知道。
  • 最少蒐集：只拍需要的區域，不拍浴室、臥室床上；能不存影像就不存，只存事件。
  • 只存本機、定期刪除：影像與對話不上傳雲端；設定保存天數並真的執行刪除。
  • 隱私模式：長輩要能自己按一下就暫停錄影，這是尊重，不是漏洞。
  • 人臉辨識：屬於高度敏感的生物特徵資料；沒有取得本人同意，不要建立人臉資料庫。
  • 系統不是醫療設備：它只能輔助，不能取代人的照顧與醫療判斷；報告與展示時要清楚說明。
  • 金鑰安全：Webhook、Token、API 金鑰只放 .env，外洩就立刻作廢重發。
  • 家電安全：會發熱或有危險的設備必須二次確認，並保留紀錄。
