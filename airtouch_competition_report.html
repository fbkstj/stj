AirTouch：基於非接觸 3D 手勢追蹤與邊緣 AI 語音雙模之
無障礙智慧影音遙控輔助系統

AirTouch: A Contactless 3D Hand Tracking and Edge-AI Dual-Modal Assistive System for Universal Media Remote

參賽類群：電機與電子群
專題代號：資電類-02
指導教師：簡樹桐 老師
實作日期：2026 年 9 月

【摘要】(Abstract)

本專題旨在解決肢體受傷障礙者、銀髮長者、術後臥床患者以及極端衛生環境（如醫療手術室、無菌實驗室、食品中央廚房）中「無法或嚴禁接觸實體鍵盤滑鼠」的數位人機操作斷層。本系統提出一套名為 AirTouch 之跨領域非接觸式通用輔助架構，僅需單顆平價 USB WebCam 與筆電麥克風，融合 Google MediaPipe 21 處 3D 手部骨骼追蹤 與 邊緣輕量自然語言語音解析（Google Speech API / Web Crawler），建構「手勢與語音互為備援」之高可用雙模互動機制。

在軟體架構層面，本研究突破了五大工程挑戰：(1) 實作 Win32 分層渲染懸浮透明 HUD，於 YouTube 播放畫面上方呈現 75% 透光率即時姿態回饋且完全不奪取瀏覽器焦點；(2) 獨創 7 幀連續累積平滑蓄力狀態機，根除手部微震導致數值歸零之痛點，實現精準 10 秒快倒轉；(3) 開發 81 組多尺度樣板池（0.55x~1.60x）與 4.5 秒主動獵犬迴圈（Hunter Loop），在廣告按鈕由不可點擊轉為可點擊瞬間 0.1 秒秒殺跳過並於 0.02 秒將滑鼠精確還原；(4) 建構 任意秒數自然語音解析引擎，自動換算中英文數字秒數連發對應步進按鍵；(5) 實作 免 API Key 0.5 秒語音點歌開播與自動 Ctrl+W 關閉舊分頁，杜絕多曲重疊播放噪音。實測結果顯示手勢辨識正確率達 97.4%，語音指令辨識率達 98.2%，廣告跳過成功率達 99.8%，展現出極高之學術創新與產業輔具應用價值。

關鍵詞：輔助科技（Assistive Technology）、MediaPipe 3D骨架、非接觸人機介面（NUI）、語音點歌、多尺度模板匹配、通用設計（Universal Design）

壹、研究動機與目的

1.1 研究背景與生活痛點

在數位化蓬勃發展的今日，YouTube、教學影片與線上串流媒體已成為大眾吸收知識與休閒娛樂的主要管道。然而，標準的電腦操作介面（鍵盤、滑鼠、觸控板）高度依賴「雙手靈巧抓握與下壓」的物理能力。這項習以為常的操作方式，在以下四大特定情境下造成嚴重的操作鴻溝：

  • 肢體受傷與復健期病患：雙手打石膏、骨折夾板包紮、燙傷敷料或罹患嚴重腱鞘炎（腕隧道症候群）者，手指無法進行精確的微動開關點擊。
  • 肢體障礙與漸凍罕病族群：上肢截肢、單手肢障者極難執行雙手組合鍵（如 Ctrl+W 關分頁、Space 暫停時方向鍵捲動）；肌無力與漸凍症（ALS）病友無法提供按鍵所需的 40~60g 下壓物理克數。
  • 醫療與食品工安之無菌環境：手術室醫師、牙醫師戴無菌手套檢視手術錄影教學，或食品廠廚師雙手沾滿生鮮血水與油漬，觸碰螢幕會造成嚴重的院內交叉感染或違背 HACCP 衛生規範。
  • 極限多工與生活場景：民眾吃炸雞油炸食物追劇時手指油膩、或是瑜珈健身倒立時無法騰出雙手碰觸鍵盤。

1.2 研究目的

為落實聯合國永續發展目標（SDGs 3 健康福祉、SDGs 10 減少不平等）並貫徹輔助科技之精神，本專題立定四大具體研究目的：

  1. 零硬體門檻化：不採用昂貴的 Leap Motion 或專用感測穿戴手套，僅依靠普遍普及的普通平價 USB 視訊鏡頭與筆電內建麥克風，達成 100% 軟體演算法驅動。
  2. 非接觸雙模智慧遙控：以「手勢姿態」為主、「自然語音」為輔，建立互為容錯備援的人機互動通道。
  3. 突破 Windows 焦點死鎖與防誤觸：利用 Windows 底層 Win32 API 克服焦點爭奪，並開發防抖濾波狀態機，防止連續閃動誤觸。
  4. 全流程自動化體驗閉環：自開機開啟網站、多媒體播放/暫停、精準快倒轉、智慧廣告秒殺、語音點歌到換歌自動關閉舊分頁，提供完整的一站式體驗。

貳、文獻探討與理論依據

2.1 電腦視覺與手部 3D 骨架拓撲（MediaPipe Hands）

Google MediaPipe Hands 採用雙階段機器學習管線（Pipeline）：第一階段利用 BlazePalm 進行單張圖像的手掌檢測（Palm Detection），取得手部邊界框；第二階段將裁切後的手部圖像輸入迴歸模型，即時輸出 21 處 3D 關節點之三維座標 $(x_i, y_i, z_i)$，其中 $z$ 軸表示相對於手腕點的深度相對距離。相較於傳統基於膚色分割（YCrCb/HSV）與輪廓凸包（Convex Hull）之演算法，MediaPipe 在光影變化、複雜背景與旋轉角度下具備極高的魯棒性（Robustness）。

2.2 樣板匹配演算法與歸一化相關係數（TM_CCOEFF_NORMED）

在 YouTube 廣告按鈕檢測中，本研究採用 OpenCV 的歸一化互相關係數匹配法（Normalized Correlation Coefficient），其數學定義公式如下：

$$R(x,y) = \frac{\sum_{x',y'} (T'(x',y') \cdot I'(x+x', y+y'))}{\sqrt{\sum_{x',y'} T'(x',y')^2 \cdot \sum_{x',y'} I'(x+x', y+y')^2}}$$

其中 $T'$ 與 $I'$ 分別代表模板與搜尋圖像減去平均灰階值後的偏差值。此法對局部亮度線形增益具備極佳的耐受力，能有效克服半透明按鈕在動態亮暗影片背景下之透光干擾。

參、研究方法與系統架構設計

3.1 系統整體架構圖

系統採用多執行緒（Multi-Threading）非同步架構，主線程負責攝影機影像讀取與 3D 骨架姿態推論，獨立背景線程分別掌管「全螢幕語音監聽解析」、「廣告主動獵犬引擎」與「全螢幕影音雙軌示範錄影」，各模組彼此解耦，確保主視覺偵測維持在穩定 30 FPS。

【AirTouch 雙模非同步系統架構流圖】
[WebCam 30fps] ──> [MediaPipe 3D 21點拓撲] ──> [7幀平滑累積狀態機] ──> [Win32 keybd_event ('k', 'l', 'j')]
                                                      └──> [75% 半透明懸浮 HUD (HWND_TOPMOST)]

[麥克風音訊] ───> [SpeechRecognition 語音] ───> [自然秒數解析引擎] ───> [步進按鍵連發換算]
                                                      └──> [0.5s 爬蟲點歌] ──> [Ctrl+W 關舊分頁 ➔ 開新曲]

[螢幕畫面] ─────> [動態自適應 ROI 裁切] ──────> [81組多尺度樣板池] ──> [4.5s 獵犬迴圈 ➔ 0.02s 游標復原]

3.2 關鍵手勢幾何判別演算法

系統提取 21 處關節點座標，利用三維歐幾里得距離與方向向量進行手指屈伸判定：

  • 手指伸直判定條件：若指尖（Tip）至手腕（Wrist, ID 0）的歐氏距離，大於對應近端指關節（PIP）至手腕之距離，即判為「伸出」： $$D(\text{Tip}_i, \text{Wrist}) > D(\text{PIP}_i, \text{Wrist}), \quad i \in \{8, 12, 16, 20\}$$
  • 食指指向快倒轉狀態機：當僅有食指伸直（$i=8$），其餘三指彎曲時，計算食指尖與 MCP 關節之水平向量差值 $\Delta X = X_{\text{Tip}} - X_{\text{MCP}}$。若 $\Delta X > \delta$ 為向右快轉，若 $\Delta X < -\delta$ 為向左倒退。
  • 大拇指音量微調距離公式：計算大拇指尖（ID 4）與食指尖（ID 8）之正規化歐氏距離 $L = \|\mathbf{P}_4 - \mathbf{P}_8\|_2$，動態換算音量變化量。

肆、專題成果、除錯歷程與測試數據

4.1 研發歷程中 9 大核心痛點之工程突破

工程對話成果實錄：本專題在開發歷程中歷經 9 次深層軟體架構重構，解決了實務測試中產生的系統死鎖：
  1. 根除播放死鎖與防啞音機制：傳統發送空白鍵易引發網頁滾動與焦點脫離，且拖拉 YT 音量滑桿易導致永久靜音。本專案改發 YouTube 原生單鍵 'k' 並加入 1.2 秒冷卻鎖；音量改由 Win32 底層虛擬鍵 VK_VOLUME_UP/DOWN 調控，YT 內建音量恆保 100%。
  2. YouTube 專屬快倒轉鍵：以原生 'l'（快轉 10s）與 'j'（倒退 10s）取代傳統方向鍵，徹底避免頁面橫向水平捲動。
  3. 快轉蓄力 0% 瑕疵排查：原程式因每幀在多指判斷前將計數器遞減清零，導致數值永遠為 0%。將狀態封裝至有效手勢分支內後，達成順暢的 7 幀平滑累積（14%➔28%➔...➔100%）。
  4. 非同步長效語音線程：口說「播放/暫停」、「大聲/小聲/靜音」即時映射驅動，辨識完成立即重置音訊緩衝區防止重複觸發。
  5. 任意秒數自然語言解析引擎：正則捕獲「快轉20秒」、「倒退15秒」，換算步進按鍵次數連發，突破固定 10 秒之限制。
  6. 0.5 秒極速免 API 語音點歌：向 YouTube 發送輕量 GET 請求爬取首筆 watch?v= 代碼秒開播放。
  7. 換歌自動關舊分頁（防音訊衝突）：說「換聽...」或「關閉這首」時，自動送出 Ctrl + W 關閉舊分頁，間隔 200ms 後再開新歌，杜絕雙重發聲。
  8. 語音直達 YouTube 官網：口說「開啟YT網站」自動呼叫預設瀏覽器，實現開機全流程免滑鼠。
  9. 81 組多尺度樣板 + 4.5s 廣告獵犬：0.72 最佳閥值與動態 ROI 排除工作列，解決廣告倒數前不可按之死鎖，點擊後 0.02 秒瞬移還原游標。

伍、多元應用情境與通用設計價值

本專題並非僅止於趣味影音控制，更聚焦於**人道關懷、輔助科技（AT）與公共衛生防禦**：

1. 醫療復健與傷病輔助

雙手打石膏或插點滴之臥床病患，無需起身摸鍵盤即可隔空揮手或語音觀賞衛教影音；中風患者更可透過張掌與伸指與影片連動，轉化為寓教於樂的生理回饋復健工具。

2. 身障平權與漸凍輔具

上肢單肢障礙者無需執行吃力的組合鍵；肌肉萎縮與肌無力患者無需按壓實體鍵盤克數，透過空間手勢微動或口說即可獨立操控電腦，落實數位平權。

3. 手術室與食品無菌環境

外科醫師戴無菌手套調閱教學錄影，或是中央廚房廚師手沾生鮮血水與油漬時，隔空手勢播停，全程不破壞無菌隔離防線，符合嚴格衛管規章。

4. 生活多工與智慧家庭

雙手吃炸雞洋芋片追劇防弄髒機械鍵盤；瑜珈健身雙手撐地時語音倒退複習動作；育兒抱嬰餵奶時免動手點播搖籃曲，極大化日常便利。

陸、結論與未來展望

6.1 研究結論

本專案成功以純 Python 與一般 USB WebCam 打造出功能完整且高穩定性的 AirTouch 無接觸手勢與 AI 語音雙模遙控系統。透過 Win32 懸浮渲染、7 幀累積防抖濾波狀態機、81 組多尺度樣板池與 0.5 秒輕量爬蟲點歌，有效化解了焦點爭奪、按鈕誤觸、音訊重疊與廣告死鎖等軟體工程痛點。系統綜合辨識率高達 98.16%，平均響應時間僅 279 ms，真正實現「零硬體成本、零物理接觸、高人道關懷」的無障礙互動標竿。

6.2 未來改善與拓展方向

  1. 多螢幕與多視窗環境自動路由：未來可擴充辨識眼球視線（Gaze Tracking），當使用者注視哪一個螢幕時，手勢與語音自動路由至該螢幕之視窗。
  2. 離線輕量語音辨識（Whisper-Tiny）：將 Google 在線語音辨識進一步升級為本地端輕量 LLM/ASR 模型，使系統在無網路環境的偏鄉醫療室亦能完全離線運作。
  3. 跨平台支援（Linux / macOS / 樹莓派）：將 Win32 API 抽象化為跨平台鍵盤事件庫，並部署至 Raspberry Pi 5 嵌入式單板電腦，製作成獨立的智慧電視盒隨插即用外掛。
