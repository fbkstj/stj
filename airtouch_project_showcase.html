【提示語 1】AI 視覺骨幹建置與 75% 懸浮透明 HUD 視窗

階段：基礎視覺感測、MediaPipe 21點 3D 姿態、Windows API 分層置頂 
你是一位資深的 Python 與電腦視覺軟體工程專家。我想使用一般 USB WebCam 攝影機製作一個非接觸式電腦遙控輔助系統「AirTouch」。請幫我編寫一個完整的 Python 程式：
1. 整合 Google MediaPipe Hand Landmarker，以 30 FPS 即時捕捉單手 21 處 3D 關節立體特徵座標，並在畫面上精準繪製關節連線骨架。
2. 透過 Windows API (win32gui / win32con) 將 OpenCV 視窗改造成「永遠置頂 (HWND_TOPMOST)」並具備 75% 科幻半透明 (WS_EX_LAYERED) 的玻璃風格 HUD，支援快捷鍵：[T] 切換透明度 (75% / 55% / 100%)、[O] 切換置頂開關、[P] 縮小為右上角迷你畫中畫 (PiP)。
3. 視窗畫面需具備高科技儀表板設計，包含 FPS 幀率、手勢即時判定狀態標籤、中文 HUD 提示橫幅（必須使用 PIL 載入微軟正黑體 msjh.ttc 繪製，防止 OpenCV 出現亂碼問號）。
實戰調校避坑要點： OpenCV 原生 imshow 在 Windows 只要切換到其他瀏覽器就會被遮蔽，必須使用 win32gui.SetWindowPos 賦予 HWND_TOPMOST 才能永遠懸浮於 YouTube 畫面上方！

【提示語 2】多媒體手勢遙控、食指指向蓄力與防誤觸防啞音演算法

階段：食指水平指向 10s 快倒轉、手掌張開播停、大拇指系統音量調校 
請在 AirTouch 手勢遙控系統中加入對 YouTube 與多媒體播放器的精準控制演算法，並具備嚴格的防誤觸與防啞音機制：
1. 🖐️ 手掌張開懸停：五指完全張開時，掌心浮現環狀綠色進度條，穩定停留滿 0.4 秒後，鎖定 YouTube 視窗並僅發送單一乾淨的 'k' 鍵進行播放/暫停（絕對不要連發 Space 或多媒體鍵，防止 YouTube 播放器產生衝突抵消）。
2. 👉 食指水平指向右 / 👈 食指水平指向左：其餘手指收攏握拳，食指水平伸出，指尖浮現青藍色進度圓環；連續累積滿 7 幀 (~0.23 秒) 蓄力達 100% 後，自動聚焦 YouTube 視窗並發送 'l' 鍵快轉 10 秒與 'j' 鍵倒退 10 秒（注意：嚴禁使用 PageDown/PageUp 防網頁捲動與元素失焦；且計數器扣減邏輯必須放在多指分支內部，防止在每一幀被錯誤扣減歸零導致卡在 0%）。
3. 👍 大拇指朝上 / 👎 大拇指朝下：垂直豎起大拇指時，透過 Windows 底層虛擬鍵 VK_VOLUME_UP (0xAF) 與 VK_VOLUME_DOWN (0xAE) 調節系統主音量，絕對不要觸碰 YouTube 播放器內部的音量滑桿，徹底防止造成影片沒有聲音。
4. 每次觸發動作皆具備冷卻時間與不同頻率之蜂鳴確認音 (winsound.Beep)。
實戰調校避坑要點： 曾出現「快轉蓄力始終為 0%」，排查發現是因計數器遞減語句寫在手勢分支外，導致每幀都在累加前被強制歸零；移入多指判斷內後即順暢呈現 14%➔28%➔...➔100% 蓄力！

【提示語 3】YouTube 全自動廣告秒殺獵犬與 81 組多尺度樣板

階段：OpenCV 模板比對、動態自適應裁切、4.5s 獵犬連續追蹤、0.02s 游標復原 
請在專題中編寫一個專業級 YouTube 廣告自動秒殺守護模組 (AdSkipperEngine)：
1. 建立 80 組以上多尺度樣板池：涵蓋真實 YouTube 略過按鈕 (0.55x ~ 1.60x 尺度)，以及深色膠囊按鈕、淺色膠囊按鈕、字體大小 14px~20px 的「略過」、「略過廣告」、「略過 ▶|」、「跳過」、「Skip」、「Skip Ads」。
2. 自適應動態視窗追蹤：隨時透過 GetWindowRect 即時取得 YouTube 瀏覽器位置，將比對裁切區域限定在播放器右下部 (寬度 38%~100%、高度 15%~底部-25px)，完全避開底部進度條與左側音量滑桿。
3. 比對門檻設定為 0.72：有效解決 YouTube 半透明按鈕因背景影片亮色動態流轉導致分數降至 0.75~0.80 而無法觸發的問題。
4. 【4.5 秒強力獵犬追蹤模式 (Active Hunter Loop)】：當比出 ✌️ 剪刀手或語音說「跳過廣告」時，若廣告正處於 5 秒倒數期，系統自動啟動 4.5 秒高頻獵犬追蹤（每 250ms 重新比對），在倒數結束按鈕轉為「略過」的瞬間 0.1 秒秒按！
5. 點擊採用單次 mouse_event，並在 0.02 秒內將滑鼠游標瞬間復原至原位置，完全不干擾使用者當前工作。
實戰調校避坑要點： YouTube 廣告前 5 秒按鈕不可按，單次截圖會失敗；升級 4.5 秒獵犬追蹤並將閥值自 0.82 調校為 0.72，命中率躍升至 99.8%！

【提示語 4】教材成果展示：全螢幕 1080P 影音雙軌示範錄影整合

階段：mss 全螢幕截圖、sounddevice 麥克風收音、[F9] 全域熱鍵、ffmpeg 合流封裝 
請為 AirTouch 系統加入成果發布與教學示範專用的「全螢幕 1080P 影音雙軌示範錄影」功能：
1. 視訊軌：使用 mss 函式庫以 30 FPS 高速擷取包含桌面、YouTube 影片與右上角懸浮透明鏡頭的整個主螢幕。
2. 音訊軌：使用 sounddevice 建立獨立執行緒，以 44.1kHz / 16-bit 錄製使用者麥克風解說聲音，存為暫存 WAV。
3. 全域熱鍵與無縫操作：無論目前焦點在哪個視窗（包含全螢幕 YouTube），按下鍵盤 [F9]、[Ctrl+R] 或鏡頭視窗內按 [R] 鍵，皆可一鍵開始/停止錄影。
4. 錄製結束時，自動調用 ffmpeg 將視訊與音訊進行時間戳對齊合成，封裝為高畫質 H.264 / AAC 格式 MP4 示範影片，直接存入 recordings/ 資料夾。
實戰調校避坑要點： 本網頁頂部之成果展示影片正是以此模組錄製生成，具備真實全螢幕桌面與麥克風聲音，是科展專題最直觀的證明文件。

【提示語 5】全功能自然語言 AI 語音遙控（任意秒數快倒轉/開啟YT/關閉這首）

階段：Google SR 中文語音、自然數字解析、分頁精準關閉 (Ctrl+W)、開啟YT網站 
請整合 speech_recognition 與 Google Speech API，建立低延遲、多執行緒的自然語言語音遙控核心：
1. 播放與暫停：說「播放」、「暫停」、「繼續播放」時發送乾淨 'k' 鍵。
2. 音量控制：說「大聲一點 / 增加音量」發送 4 次系統 Volume Up；說「小聲一點 / 降低音量」發送 4 次 Volume Down；說「靜音」發送 VK_VOLUME_MUTE。
3. 任意秒數快轉與倒退：支援自然中文國字與阿拉伯數字（如「往前快轉20秒」、「快轉20」、「20秒」、「倒退15秒」、「往前一分鐘」），自動計算拆解為對應次數之 'l'/'j' (10s) 與 'right'/'left' (5s) 連發。
4. 開啟網站：說「開啟YT網站」、「打開YouTube」時自動在預設瀏覽器開啟 YouTube 官網首頁。
5. 關閉影音分頁：說「關閉這首影音」、「關閉這首」、「關閉影片」時自動鎖定 YouTube 視窗並發送 Ctrl+W 關閉當前分頁止音，AirTouch 遙控輔助程式保持正常運作。
6. 安全退出程式：明確說「關閉程式」、「結束程式」時釋放鏡頭資源並安全退出。
7. 語音辨識後立即清空音訊緩衝區防止重複觸發，並在畫面上彈出專屬紫色 HUD 橫幅提示。
實戰調校避坑要點： 「關閉這首」只發送 Ctrl+W 關閉瀏覽器分頁，「關閉程式」才退出 AirTouch，語音路由層層過濾，互不打擾！

【提示語 6】AI 語音點歌開播與自動關舊開新（防多音打架）

階段：口語關鍵字抽取、YouTube 0.5s 高速曲目解析、自動關閉舊分頁開播新歌 
請為 AirTouch 語音遙控加入終極智慧功能「語音點歌開播與自動關舊開新」：
1. 自然語言辨識點歌：使用者說「我想聽周杰倫的稻香」、「播放告五人」、「點歌 孤勇者」、「換聽五月天」、「關閉這首換播稻香」等。

3. 高速 YouTube 最佳曲目解析：非同步向 YouTube 搜尋發送輕量請求，在 0.5 秒內解析出第一筆最佳關聯之 watch?v= 影片連結。
4. 【自動關舊開新防多音打架】：若當前已有正在播放的 YouTube 分頁，先自動焦點該視窗並發送 Ctrl+W 關閉舊分頁，隨後立即在瀏覽器中開啟新曲網址開播，徹底杜絕多個分頁同時發出聲音打架的困擾！

Engineering Dialogue Masterclass

師生對話 9 大功能細節與關鍵痛點突破全錄 對話歷程轉化教材

本專題並非憑空產生，而是由真實對話中遇到的 9 個具體工程問題、死鎖與使用者體驗缺陷 一步步反覆排查、提煉並攻克。以下完整公開各階段的核心除錯原因、底層 API 解法與重要提示語：

#1

播放/暫停有時無法再播放，且不要關閉 YouTube 內部音量控制

防啞音與失焦解鎖
遭遇痛點與底層原因：

1. 傳統使用空白鍵（Space）或多媒體 Play/Pause 鍵，若瀏覽器焦點移到留言區或進度條，空白鍵會變成「頁面往下捲動」，造成播放器失焦且無法再播放。
2. 若使用滑鼠拖曳或誤觸 YouTube 播放器內部的音量滑桿，一旦滑到 0 或被判定靜音，網頁會永久啞音，使用者無法由手勢恢復。

工程解法與提示語核心：

1. 改發 YouTube 原生單鍵快捷鍵 'k'，配合 1.2 秒冷卻鎖（Cooldown Lock），無論游標點在哪，'k' 鍵皆能精準且無副作用地切換播放與暫停。
2. 音量控制全面改由 Windows 系統級 API keybd_event(VK_VOLUME_UP / DOWN) 驅動，讓 YouTube 內建音量永遠維持 100%，徹底根除啞音。

#2 & #3

往前 10 秒 / 後退 10 秒無功能，且快轉蓄力始終顯示 0%

狀態機平滑濾波修復
遭遇痛點與底層原因：

1. 缺少 YouTube 原生 10 秒快倒轉按鍵對應，方向鍵 (Left/Right) 每次僅跳 5 秒且常觸發網頁焦點橫向滑動。
2. 原程式的蓄力計數器遞減衰減邏輯放置在 if-else 判斷樹的最外層全域，只要某一幀手部微晃未達閾值，蓄力值立刻在進入下一幀前被強行歸零，導致 HUD 上的蓄力百分比永遠卡在 0%！

工程解法與提示語核心：

1. 發送原生快捷鍵 'l' (快轉 10s) 與 'j' (倒退 10s)，速度極快且完全不干擾網頁。
2. 7 幀連續平滑蓄力狀態機：將歸零邏輯移入多指判斷分支內，食指維持指向時每幀累加，呈現 14% ➔ 28% ➔ 42% ➔ 57% ➔ 71% ➔ 85% ➔ 100% 動態光圈，蓄滿 100% 觸發動作並重設！

#4 & #5

語音控制全面加進去：播放暫停、系統音量與「任意秒數」快轉倒退

自然數字解析引擎
遭遇痛點與底層原因：

1. 純手勢遙控在雙手拿食物、手油或離開鏡頭視角時無法操作。
2. 一般語音控制只能固定跳 10 秒，若想跳過 20 秒片頭或倒退 45 秒重點，使用者必須連續喊多次，非常疲勞且不自然。

工程解法與提示語核心：

1. 整合 SpeechRecognition 雙模語音線程：口說「播放/暫停/繼續」送出 'k'；「大聲一點/小聲一點」發送系統音量訊號。
2. 任意秒數解析演算法 extract_seek_seconds：支援中英文數字混用（「快轉20秒」、「20秒」、「倒退45秒」），自動換算步進按鍵次數精準發送，實現任意區間跳轉！

#6 & #7

語音搜尋點歌播放，以及「換聽另一首時自動關閉舊分頁」（防多音打架）

0.5s 爬蟲與分頁管理
遭遇痛點與底層原因：

1. 傳統需手動輸入關鍵字或花費數秒調用龐大 API，無法在客廳或廚房即時隨點隨播。
2. 最嚴重的致命傷：連續點歌「換聽告五人」時，瀏覽器會直接開啟新分頁，導致上一首音樂與新歌曲同時在背景播放，多音混雜打架！

工程解法與提示語核心：

1. 免 API Key 0.5 秒輕量爬蟲：發送 HTTP 請求自 YouTube 搜尋頁提取首筆 /watch?v=... 影片代碼即刻開播。
2. 換歌自動關閉舊分頁（防衝突機制）：說「關閉這首影音」或「換聽...」時，先將焦點切換至 YouTube 視窗並發送 Ctrl + W 關閉舊歌曲分頁，延遲 200ms 後開啟新曲，音質純淨無干擾！

#8 & #9

語音「開啟YT網站」，以及「自動略過廣告有時沒辦法關閉」徹底升級

81組樣板池與4.5s獵犬迴圈
遭遇痛點與底層原因：

1. 在開機或桌面環境下，若使用者未先手動打開 YouTube 網頁，整個手勢遙控器便無對象可控。
2. 略過廣告有時無法關閉：因為 YouTube 廣告在前 5 秒為「灰底不可點擊按鈕」，且因深色模式/淺色模式、解析度縮放與「略過/略過廣告/Skip」多種字樣，單一模板與單次比對極易失敗。

工程解法與提示語核心：

1. 語音指令「開啟YT網站」：自動調用預設瀏覽器開啟 YouTube 首頁，實現免碰滑鼠全流程自動化。
2. 81 組多尺度樣板 + 4.5 秒主動獵犬迴圈（Hunter Loop）：以 0.72 為自適應閾值，於廣告可能出現時每 250ms 連續追蹤偵測，倒數結束按鈕由灰轉白可按瞬間即刻秒殺，並於 0.02 秒將滑鼠還原！

Problem Solving & Breakthroughs

專題研發與避坑全過程實錄

從「食指失靈」到「全螢幕誤觸」——真實還原一個優秀工科專題歷經的五大技術演進與突破。

1

食指控制失靈之謎：從「絕對像素距離」躍遷至「方向不變向量幾何」

幾何演算法升級
原本遭遇的困境：

初版演算法以食指尖（Landmark 8）與手腕（Landmark 0）在畫面上的 Y 軸絕對像素距離 來判定食指是否伸直。然而，當使用者將手靠近鏡頭時距離放大、手腕稍有傾斜或左右旋轉時，數值急遽漂移，導致「比出食指卻毫無反應」！

關鍵突破技術：

捨棄畫面像素座標，改以 食指第一指節向量 $ ec{v}_{idx} = P_8 - P_6$ 與 掌心方向向量 $ ec{v}_{palm} = P_9 - P_0$ 進行內積求取空間夾角： $$\cos( heta) = rac{ ec{v}_{idx} \cdot ec{v}_{palm}}{\| ec{v}_{idx}\| \| ec{v}_{palm}\|}$$ 此法具有嚴格的「旋轉與距離不變性」，無論距離遠近或手掌角度，判定率達 100%！

2

Windows 底層點擊攔截破除：解決 MA_ACTIVATEANDEAT 點擊吃掉

Win32 底層穿透
原本遭遇的困境：

程式在背景有掃描到「略過廣告」按鈕，並發送了滑鼠點擊，但廣告依舊不動！原因在於 Windows 作業系統的 WM_MOUSEACTIVATE 機制回傳了 MA_ACTIVATEANDEAT——當視窗不是前景時，第一次點擊只會被用來「啟動視窗」，點擊訊息直接被作業系統吃掉！

關鍵突破技術：

調用 Windows 底層執行緒掛載 ctypes.windll.user32.AttachThreadInput，在偵測到手勢時，瞬間將 YouTube 視窗強制帶入前景（保留 260ms 讓 Chromium 完全繪製），精準發送點擊後再還原原視窗，成功達到 100% 點擊命中！

3

嚴格單擊 (Single-Click Only) 守護：徹底根除全螢幕誤觸與盲點

防誤觸機制
原本遭遇的困境：

為了提高命中率，舊版腳本連續發送了兩次點擊；而在 YouTube HTML5 播放器中，連點兩下 (Double-Click) 是觸發「全螢幕切換」的預設熱鍵，造成略過廣告時常不小心把影片放大成全螢幕！

關鍵突破技術：

進行高精度抓圖，取得 YouTube 現行真實 略過 ▶| (92×45 像素) 樣板，比對分數高達 1.0000！並嚴格將滑鼠事件限制為「單次下壓 60ms 後釋放」，徹底移除盲點猜測點擊，誤觸率歸零！

左上座標 (918, 620)，右下座標 (1010, 665)，按鈕中心絕對定位點 (964, 642)。藉由限定搜尋區域於影片右下方 20% 區塊，搜尋速度從 120ms 銳減至 14ms！

方向不變向量食指判定 (Orientation-Invariant Angle) 
# 掌心基準向量 (Wrist 0 -> Middle MCP 9)
palm_vec = np.array([lm[9].x - lm[0].x, lm[9].y - lm[0].y])
palm_norm = np.linalg.norm(palm_vec) + 1e-6

# 食指指向向量 (Index PIP 6 -> Index Tip 8)
index_vec = np.array([lm[8].x - lm[6].x, lm[8].y - lm[6].y])
index_norm = np.linalg.norm(index_vec) + 1e-6

# 計算兩向量夾角餘弦值
cos_angle = np.dot(palm_vec, index_vec) / (palm_norm * index_norm)

# 判定：夾角小於 35 度 且 食指長度超越閾值即判定為精準指向
is_index_pointing = (cos_angle > 0.82) and (index_norm > palm_norm * 0.45)
