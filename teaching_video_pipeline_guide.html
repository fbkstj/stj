1. 工作流全景圖與架構概述

把數小時的課堂錄影，透過 Python 腳本與 AI 語音辨識，轉成有片頭、繁體中文字幕、並整理成 YouTube 播放清單的線上課程。每個階段都是獨立的腳本，可以只重做其中一段（例如改了字幕規則，只要重跑字幕與壓製）。

01

長空白偵測（選用）

只抓 8 秒以上的空白並列出時間點，人工確認後才裁切；裁切一律重新編碼並固定 30 fps。trim_silence.py

02

語音辨識與繁體化

Faster-Whisper＋VAD、逐字時間戳、關閉「延續前文」防跳針；專有名詞用 hotwords；OpenCC 轉台灣繁體。transcribe.py

03

單行字幕重組

依逐字時間在標點與停頓處斷句：每行最多 20 字、停留時間跟著講話、絕不重疊。subtitles.py

04

片頭、壓製與發布

1080p 片頭圖卡＋4 秒片頭、統一規格後壓製；YouTube 上傳、CC 字幕、播放清單。render.py、upload.py

python run_pipeline.py --episodes 1     # 第一次先做一集（到壓製完成，不上傳）
python upload.py --dry-run              # 先看要上傳什麼
python upload.py                        # 確認後才上傳

2. 第一階段：原始檔整理與設定檔

良好的檔案結構是自動化順利運作的基石。課程相關的資料（檔名、標題、日期、術語）全部寫在 config.json，換一門課只要換設定檔，不用改程式。

資料夾結構建議

d:\影片編輯\115-09-07-AI課程\
├── 第01節課_45分鐘分段_000000至004500.mp4
├── 第02節課_45分鐘分段_004500至013000.mp4
├── ...
└── output/
    ├── trimmed/           # 裁切後的影片（有做才會有）
    ├── transcriptions/    # 語音辨識結果（含逐字時間）
    ├── subtitles/         # epXX.srt（給 CC）與 epXX.ass（燒字幕用）
    ├── covers/            # 1080p 片頭圖卡與 4 秒片頭
    ├── final_videos/      # 成品影片
    ├── logs/              # 每一次 ffmpeg 的完整紀錄
    └── uploads.json       # 已上傳的影片 ID（中斷後再跑不會重傳）

config.json 重點欄位

"episodes": [ {"file": "第01節課_….mp4", "title": "【115-09-07 AI課程】第 01 節課：…"} ],
"whisper":  {"model": "large-v3-turbo", "initial_prompt": "這是台灣高職 AI 應用與實務課堂教學。",
             "hotwords": "AI Python ChatGPT Prompt LLM ESP32 Arduino 物聯網 PCB"},
"subtitles":{"max_chars": 20, "min_duration": 1.2, "max_duration": 6.0, "max_cps": 8,
             "replacements": {"序列布": "序列埠"}},
"render":   {"subtitle_mode": "cc"}
💡 命名關鍵技巧

使用有明確集數序號（如 第01節課、ep01）的檔名，排序與對照都不會錯；檔名可以有中文，但避免 ' 等特殊符號。

3. 第二階段：長空白偵測（先報告、再裁切）

課堂影片裡「沒有聲音」不等於「沒有內容」：老師可能正在寫板書、示範操作，學生在實作。所以不要把每一段安靜都剪掉，只處理很長的空白（例如忘記停錄、下課時間），而且要先看過再剪。

FFmpeg silencedetect 參數

ffmpeg -i input.mp4 -af silencedetect=noise=-35dB:d=8 -f null -
參數 建議設定 說明
noise -35dB（教室有冷氣風扇聲可試 -30dB） 低於這個音量算安靜。門檻設太高，連小聲講話都會被當成空白。
d (duration) 8 秒以上 安靜超過這個秒數才列出來。1.5～2 秒的短停頓是正常講話節奏，交給語音辨識的 VAD 處理即可，不要剪。
保留邊界 前後各 0.5 秒 空白頭尾各留一點，接起來才不突兀。
⚠️ 裁切一定要重新編碼，並固定影格率

用 -c copy 在非關鍵影格的位置切，會造成聲音與畫面不同步；沒有鎖定影格率（fps=30），多次重新編碼後畫面會慢慢落後聲音。技能包的 trim_silence.py --apply 用 select／aselect 一次裁切並重新編碼成固定 30 fps。

python trim_silence.py                        # 只列出每集的長空白時間點（不改檔案）
python trim_silence.py --episodes 3 --apply   # 看過確定後才裁切

4. 第三階段：Whisper 語音辨識、防幻覺與專有名詞

為了提升台灣高職電機電子群課程專有名詞的辨識率，同時避免 Whisper 常見的「跳針」幻覺，這個階段有三件事要做對：防幻覺參數、專有名詞放對地方、一定要有逐字時間。

⚠️ 重大陷阱：重複幻覺（跳針）

Whisper 預設會把「上一段的結果」當成下一段的提示（condition_on_previous_text=True）。一旦某段認錯或遇到安靜、低音量的片段，錯誤就會一路延續，變成同一句話重複幾十次，或把提示詞本身當成字幕吐出來。關掉它是最有效的一招；把 initial_prompt 縮短也有幫助。compute_type 用 int8 或 float16 只影響速度與記憶體，和幻覺無關。

🎯 專有名詞：hotwords 與同音字表
  • initial_prompt 只放一句情境，例如「這是台灣高職 AI 應用與實務課堂教學。」
  • hotwords 放專有名詞：Python、ChatGPT、LLM、ESP32、Arduino、PCB、物聯網、微控制器…（faster-whisper 1.0 以上支援）
  • 同音字表（config 的 replacements）修正仍然認錯的詞，例如 序列布 → 序列埠。

模型怎麼選

情況建議模型說明
有 NVIDIA 顯示卡large-v3-turbo中文準確度明顯比 medium 好，速度也快
只有 CPUmedium45 分鐘課程約需數十分鐘；small 較快但錯字較多
第一次調參數先剪 30 秒片段測試確認有字、有逐字時間、沒跳針，再跑整集

建議的辨識設定

from faster_whisper import WhisperModel
import opencc

model = WhisperModel("large-v3-turbo", device="cuda", compute_type="float16")   # 只有 CPU：("medium", device="cpu", compute_type="int8")
converter = opencc.OpenCC("s2twp")   # 轉台灣繁體＋台灣慣用詞；只想轉字不改詞可用 "s2tw"

segments, info = model.transcribe(
    "video_path.mp4",
    language="zh",
    beam_size=5,
    initial_prompt="這是台灣高職 AI 應用與實務課堂教學。",      # 短短一句就好
    hotwords="AI Python ChatGPT Prompt LLM ESP32 Arduino 物聯網 PCB",
    condition_on_previous_text=False,     # 防跳針：錯一段不會一路錯下去
    word_timestamps=True,                 # 逐字時間：字幕才能精準斷句（沒開就只能用猜的）
    vad_filter=True,                      # 先濾掉沒講話的部分
    vad_parameters=dict(min_silence_duration_ms=1000, speech_pad_ms=400),
    hallucination_silence_threshold=2.0,  # 長停頓附近的可疑片段直接跳過
    compression_ratio_threshold=2.4,      # 文字重複度太高（像在跳針）就重試或丟棄
    no_speech_threshold=0.6,
)
for s in segments:
    text = converter.convert(s.text.strip())
    words = [(w.start, w.end, converter.convert(w.word)) for w in s.words]

5. 第四階段：單行字幕重組規則與樣式

語音辨識常輸出 3～5 個字的碎句，直接當字幕會快速閃爍；但硬把每行拉長到固定秒數，又會和下一句重疊、在畫面上疊成兩行。正確做法是用逐字時間重新組句，並讓停留時間跟著講話走。

原則 1

永遠單行、不超寬

每行最多約 20 個中文字（英數字母算半個字寬）。ASS 加 WrapStyle: 2，播放器才不會自動折行。串流平台的中文字幕規範多在每行 16 字左右；有簡報的教學影片放寬到 20 字仍好讀。

原則 2

斷在標點與停頓

停頓超過 0.8 秒一定斷開；被字數逼著斷行時，往回找標點或最長的停頓，不要把「輸出」切成「…的輸」「出結果」。

原則 3

停留時間跟著講話走

最少 1.2 秒、最多 6 秒；講太快（每秒超過 8 字）就稍微延長，讓人讀得完。延長時絕不能蓋到下一句，否則兩行會同時出現。

原則 4

高對比、乾淨

微軟正黑體、白字、深色外框（Outline 3、Shadow 2）；句尾的逗號句號去掉、句中改成空白；中英文之間留一個空白（「用 Python 寫」）。

⚠️ 片頭秒數只能加一次

成品前面接了 4 秒片頭，字幕時間就要往後 4 秒。技能包的做法：epXX.srt 已加 4 秒（對齊成品，上傳 CC 用）；epXX.ass 不加，在接片頭之前燒進原始影片。兩邊都加或都沒加，字幕就會整條差 4 秒。

6. 第五階段：片頭合成與 FFmpeg 壓製

用 Pillow 繪製 1080p 片頭圖卡（課程名稱、上課日期、學校），做成 4 秒片頭，再和課程影片接起來壓製。接之前一定要把兩段的規格統一，否則 concat 會失敗或造成聲音畫面漸漸不同步。

片頭：圖片＋靜音音軌

ffmpeg -y -loop 1 -framerate 30 -i cover.png \
  -f lavfi -i anullsrc=channel_layout=stereo:sample_rate=48000 \
  -t 4 -vf setsar=1 -c:v libx264 -pix_fmt yuv420p -r 30 \
  -c:a aac -ar 48000 -ac 2 intro_4s.mp4

用圖片做的片頭本身沒有聲音，concat 需要每一段都有聲音軌，所以要補一條靜音音軌（anullsrc）。

接片頭＋（選擇性）燒字幕＋壓製

ffmpeg -y -i intro_4s.mp4 -i lecture_main.mp4 -filter_complex \
  "[0:v]scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=30[v0]; \
   [1:v]scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,setsar=1,fps=30,ass=ep01.ass[v1]; \
   [0:a]aresample=48000,aformat=channel_layouts=stereo[a0]; \
   [1:a]aresample=48000,aformat=channel_layouts=stereo[a1]; \
   [v0][a0][v1][a1]concat=n=2:v=1:a=1[outv][outa]" \
  -map "[outv]" -map "[outa]" \
  -c:v libx264 -preset medium -crf 20 -pix_fmt yuv420p -r 30 \
  -c:a aac -b:a 192k -ar 48000 -ac 2 -movflags +faststart \
  final_output.mp4
  • 字幕燒在課程影片 [1:v] 上、接片頭之前：ASS 的時間就不用加片頭秒數。不燒字幕（上傳 CC）時，把 ,ass=ep01.ass 拿掉。
  • setsar=1、fps=30、aresample=48000：兩段規格一致，concat 才穩定。
  • -preset medium：ultrafast 同樣畫質檔案大很多，只適合預覽；最終版用 medium（有時間可用 slow）。
  • -movflags +faststart、yuv420p：網頁、手機、LINE 都能直接播。
  • 字幕路徑不用手動轉義：在字幕資料夾裡執行 ffmpeg，ass=ep01.ass 只寫檔名，就不會遇到 Windows 磁碟機冒號、反斜線要轉義的問題。
  • 不要把 ffmpeg 的錯誤訊息丟掉：技能包把每次指令與錯誤存到 output/logs/，並檢查成品長度＝片頭＋正片。

7. 第六階段：YouTube API 上傳、CC 字幕與播放清單

透過 YouTube Data API 上傳影片、掛上繁體中文 CC 字幕、建立播放清單。技能包的 upload.py 每傳完一支就記錄在 output/uploads.json，中斷或配額用完，隔天再跑會接著傳，不會重複。

⚠️ 未通過稽核的 API 專案：影片會被鎖成「私人」

YouTube 規定：2020 年 7 月 28 日之後建立、且未通過 YouTube API 稽核的專案，用 API 上傳的影片一律限制為私人。設定成不公開或公開都不會生效。解法是申請 API 稽核（YouTube API Services Audit），或上傳後到 YouTube 工作室手動確認。upload.py 上傳後會檢查實際的隱私狀態並提醒。

字幕二選一

CC 字幕 或 燒進畫面

同時燒字幕又上傳 CC，觀眾打開 CC 會看到兩份。建議上傳 CC（subtitle_mode: "cc"）：可以開關、可以被搜尋，對需要的人也更友善；要燒進畫面就不要再上傳 CC。

配額

每天預設 10,000 單位

上傳影片是最耗配額的操作，一天通常只能傳個位數支；字幕、播放清單也會消耗（實際數字以官方配額表為準）。出現 quotaExceeded 隔天再跑即可。

可續傳＋重試

大檔案不怕斷線

用 MediaFileUpload(resumable=True) 分段上傳；遇到 500/502/503/504 或網路中斷，等 2、4、8… 秒從斷點續傳。

播放清單

加入失敗就重試

剛上傳的影片有時要幾秒後才查得到，加入播放清單會回報找不到影片。做法是失敗時等待後重試，並且不指定 position，依集數順序加入。

python upload.py --dry-run     # 先列出要上傳的內容，不連線
python upload.py               # 確認後上傳

8. 【核心專題】OAuth 7 天失效與重新授權

🚨 經典踩坑：為什麼 Refresh Token 在 7 天後突然失效？

Google Cloud 專案的 OAuth 同意畫面如果還在「測試中（Testing）」，發出的 refresh token 7 天後一定失效，執行 API 會出現 invalid_grant: Token has been expired or revoked。

💡 三個對策，各自解決不同的問題

對策 A（根本解決 7 天問題）

把 OAuth 同意畫面改成「正式發布（In production）」

登入 Google Cloud Console → 選擇專案 → OAuth 同意畫面 → 發布狀態從 Testing 改為 In production，然後重新授權一次。

注意：個人自用可以不送 Google 審查，但授權時會看到「Google 尚未驗證這個應用程式」，按「進階 → 前往」即可，且最多 100 位使用者。正式發布後 refresh token 沒有 7 天限制，但不是永久：自己撤銷授權、超過 6 個月沒使用、同一帳號對同一個用戶端授權太多次（舊的會被作廢），都會讓它失效，屆時重新授權即可。

對策 B（日常自動續期）

程式自動換新的 access token

access token 大約 1 小時就過期，程式用 refresh token 自動換新的即可。這只能處理 access token 過期，救不了 refresh token 本身被撤銷（例如 Testing 的 7 天到期），那時 refresh() 一樣會出現 invalid_grant，要改用對策 A＋重新授權。

from google.oauth2.credentials import Credentials
from google.auth.transport.requests import Request
from google.auth.exceptions import RefreshError

creds = Credentials.from_authorized_user_file("yt_token.json", SCOPES)
if not creds.valid:
    try:
        creds.refresh(Request())                       # 換新的 access token
    except RefreshError:
        raise SystemExit("授權已失效：請執行 python youtube_auth.py 重新授權")
    with open("yt_token.json", "w", encoding="utf-8") as f:
        f.write(creds.to_json())
對策 C（重新授權）

重新產生 yt_token.json

一般情況用 run_local_server 最簡單，會自動開瀏覽器、授權完自動存檔。瀏覽器開不起來時才用手動貼上的方式，而且產生網址和換 token 必須用同一個 flow 物件（新版會加上 PKCE 驗證碼，換成另一個物件就對不上）。

from google_auth_oauthlib.flow import InstalledAppFlow

flow = InstalledAppFlow.from_client_secrets_file("client_secrets.json", SCOPES)

# 一般情況：自動開瀏覽器
creds = flow.run_local_server(port=0, prompt="consent", access_type="offline")

# 瀏覽器開不起來時（同一個 flow 物件）：
# flow.redirect_uri = "http://127.0.0.1:8080/"
# url, _ = flow.authorization_url(prompt="consent", access_type="offline")
# print(url); code = input("貼上網址列中的 code：")
# flow.fetch_token(code=code); creds = flow.credentials

with open("yt_token.json", "w", encoding="utf-8") as f:
    f.write(creds.to_json())

技能包的 python youtube_auth.py（或 --manual）就是這個流程，也接受直接貼上整串網址。

9. 核心避坑總結與最佳實踐 CheckList

步驟階段 常見問題 / 踩坑點 最佳實踐解決方案
空白裁切 把寫板書、示範操作的安靜片段也剪掉；-c copy 切完聲音畫面不同步 只抓 8 秒以上的空白、先看報告再剪；裁切一律重新編碼並固定 30 fps。
語音辨識 字幕跳針、重複同一句、把提示詞當字幕 condition_on_previous_text=False＋VAD＋hallucination_silence_threshold；initial_prompt 只放一句。
專有名詞 英文縮寫、電機電子術語被認成同音字 術語放 hotwords；仍認錯的用同音字表修正；有顯示卡改用 large-v3-turbo。
字幕時間 硬拉到固定秒數，和下一句重疊，畫面變兩行 停留時間跟著講話（1.2～6 秒、每秒 ≤ 8 字），延長時不超過下一句開始時間。
字幕排版 長句被從中間切開、播放器自動折行 用逐字時間在標點與停頓處斷；每行 ≤ 20 字；ASS 加 WrapStyle: 2；MarginV 65。
片頭對齊 接了 4 秒片頭，字幕整條早 4 秒（或晚 8 秒） SRT 加片頭秒數給 CC；ASS 不加，接片頭之前燒進原始影片。
影片壓製 concat 失敗或聲音漸漸不同步；檔案太大；錯誤被隱藏 統一 setsar=1、fps=30、48 kHz；片頭補靜音音軌；preset medium＋faststart；保留 ffmpeg 紀錄。
字幕路徑 Windows 路徑的冒號、反斜線讓 ass 濾鏡讀不到檔 在字幕資料夾裡執行 ffmpeg，濾鏡只寫檔名。
OAuth 認證 7 天後 invalid_grant 同意畫面改成正式發布並重新授權；程式的自動續期只處理 access token。
上傳 影片被鎖成私人；配額用完；斷線重傳 申請 API 稽核；記錄已上傳 ID 可接續；可續傳上傳＋自動重試。
字幕重複 燒了字幕又上傳 CC，開 CC 看到兩份 二選一，建議上傳 CC。
播放清單 加入項目回報找不到影片 失敗後等待重試、不指定 position。

10. 【跨電腦移植】在另一台電腦上安裝與使用本技能

換一台全新的 Windows 電腦時，依照以下 4 個步驟設定：

步驟 1

安裝 Python 與 FFmpeg

  • Python 3.10+：安裝時勾選 Add python.exe to PATH。
  • FFmpeg：winget install Gyan.FFmpeg，裝完重開終端機，確認 ffmpeg -version 有反應。
步驟 2

解壓技能包、安裝套件、先跑測試

pip install -r requirements.txt
python tests/test_subtitles.py      # 字幕規則：通過 21 項
python tests/smoke_test.py          # 端到端：自己產生假影片跑完整流程，OK 11

第一次語音辨識會自動下載模型（medium 約 1.5 GB、large-v3-turbo 約 1.6 GB），請在網路穩定時進行。

步驟 3

設定檔與授權

  • 複製 config.example.json 為 config.json，填好影片資料夾、集數與標題、術語。
  • 要上傳 YouTube：把自己的 client_secrets.json 放進資料夾，執行 python youtube_auth.py 產生 yt_token.json。建議在新電腦重新授權，不要到處複製 token 檔；這兩個檔案等於密碼，不可放進壓縮檔、GitHub 或報告。
步驟 4

處理影片 → 檢查 → 上傳

雙擊 1_處理影片.bat（或 python run_pipeline.py）：長空白報告 → 語音辨識 → 單行字幕 → 片頭 → 壓製。看過成品與字幕後，雙擊 2_上傳YouTube.bat：先列出要上傳的內容，輸入 y 才會上傳並建立播放清單。
