00 事前準備：安裝 Antigravity（免費 AI 程式助手）

下方的 5 步提示語要貼到 Google Antigravity 的 AI 對話面板使用。它的個人方案免費，AI 能直接檢查攝影機、安裝套件、建立程式檔；一般網頁版聊天 AI 做不到這些事。已經有 Claude 付費方案的話，也可以改用 Claude Code（見下方說明）。

  1. 1. 安裝 Antigravity：到官網 antigravity.google 下載安裝（支援 Windows、macOS、Linux），用 Google 帳號登入。
  2. 2. 準備環境：安裝 Python 3.10 以上版本（安裝時勾選 Add Python to PATH），並插上 USB 網路攝影機。
  3. 3. 開啟專案資料夾：下載上方知識包並解壓縮，在 Antigravity 用「開啟資料夾」打開解壓縮後的資料夾。
  4. 4. 開始闖關：打開 AI 對話面板，依序貼上下方步驟一～步驟五的提示語。

上課前請注意

  • 免費方案每週有使用額度，用完要等額度恢復；Google 也可能調整免費額度，上課前請先實際試用一次。
  • 學生能不能用學校帳號登入，要看學校 Google 帳號的設定；不行時可改用個人帳號（請依學校規定）。
  • AI 在背景開啟的攝影機視窗不會出現在螢幕上（見下方「障礙一」），要看即時畫面時，請自己雙擊 run_ai.bat。
  • AI 要執行指令或安裝套件時，先看懂它要做什麼再同意。

也可以改用 Claude Code

下方的提示語不用修改，也能貼到 Anthropic 的 Claude Code 使用；它一樣能讀寫專案資料夾、執行指令。

  • 安裝（擇一）：
    • 下載 Claude 桌面版，登入後切到「Code」分頁，選擇解壓縮後的資料夾。
    • 在 PowerShell 執行 irm https://claude.ai/install.ps1 | iex，再到專案資料夾執行 claude。建議另外安裝 Git for Windows。
  • 費用：需要 Claude 付費方案或 Anthropic Console（API）帳號，沒有像 Antigravity 的免費方案；全班使用前請先評估。
  • 不能用的版本：claude.ai 一般聊天碰不到你電腦上的檔案；網頁版 Claude Code（claude.ai/code）在雲端執行，也用不到你的攝影機。
  • 使用差異：預設在執行指令、修改檔案前會先詢問；下方「跨對話記憶法」也可以改寫在資料夾的 CLAUDE.md，Claude Code 每次開啟都會自動讀取。
  • 攝影機即時畫面一樣建議自己雙擊 run_ai.bat 開啟。

01 步驟一至步驟五：初學闖關式提示語

針對初學者設計之依序操作步驟，附帶【任務目標】與【過關成功的樣子】。

【步驟一】相機硬體與環境體檢

任務目標：確認 USB 鏡頭有插好，檢查電腦是否已具備基礎 Python 環境。

【步驟一】請幫我檢查目前 Windows 系統上是否有連接 USB 網路攝影機（如 Logitech C270），並列出攝影機的名稱與運作狀態，以及檢查 Python 環境中是否已安裝 opencv-python 與 ultralytics。請一律使用繁體中文回覆。
過關成功的樣子：AI 回報「有偵測到攝影機，狀態 OK，OpenCV 已就緒」，即可進行步驟二。
【步驟二】下載輕量化 AI 模型核心

任務目標：下載約 6MB 的超輕量 AI 模型，讓一般筆電只用 CPU 也能即時辨識（實際 FPS 依電腦效能而定）。

【步驟二】請幫我安裝 ultralytics 庫，並在專案目錄下載最新輕量化的 YOLO11 Nano 模型（yolo11n.pt、yolo11n-pose.pt、yolo11n-seg.pt），完成後測試模型能否在 CPU 上正常進行推論。
過關成功的樣子：AI 回報「模型下載完成，CPU 測試推論通過！」，即可進行步驟三。
【步驟三】建立高穩定實時辨識程式

任務目標：生成相容性最好、不卡頓的 OpenCV 視窗程式，支援「物件、骨架、去背」熱鍵切換。

【步驟三】請在專案目錄中建立一個名為 webcam_ai_detect.py 的 Python 程式，規格如下：
1. 使用 OpenCV 開啟預設攝影機（設定解析度為 1280x720，FOURCC 設為 MJPG）。
2. 使用 YOLO11 Nano 模型進行實時推論，並在畫面上方顯示即時 FPS。
3. 支援鍵盤熱鍵即時切換：
   - 按 '1'：切換為通用物件偵測 (yolo11n.pt)
   - 按 '2'：切換為人體姿態骨架 (yolo11n-pose.pt)
   - 按 '3'：切換為實例影像分割去背 (yolo11n-seg.pt)
   - 按 'q' 或 ESC：安全關閉離開
4. 標籤名稱請對照 COCO 80 種常見類別顯示標準繁體中文。
過關成功的樣子：AI 回報已建立 webcam_ai_detect.py 且語法編譯通過，即可進行步驟四。
【步驟四】建立防閃退一鍵啟動腳本

任務目標：建立一個在任何 Windows 電腦（包含 Google 雲端虛擬硬碟）雙擊都不會閃退的啟動檔。

【步驟四】請在專案目錄建立一個 Windows 一鍵啟動批次檔 run_ai.bat：
1. 必須使用 pushd "%~dp0" 處理路徑，確保支援 Google 雲端硬碟等虛擬目錄。
2. 批次檔內容必須使用 100% 純 ASCII 英文（不得包含中文字元，避免 Windows Big5 編碼衝突導致閃退）。
3. 執行 python webcam_ai_detect.py，並在結尾加上 pause，確保出錯時視窗不會瞬間關閉。
過關成功的樣子：AI 回報已成功建立 run_ai.bat，即可進行最後一步。
【步驟五】啟動視窗與即時功能體驗

任務目標：在電腦實體螢幕上看見即時動態畫面，體驗熱鍵與物品辨識。

【步驟五】請告訴我如何正確在螢幕上看到即時攝影機視窗？請提供滑鼠雙擊啟動與終端機啟動這兩種方法，並說明啟動後如何用手勢與日常物品進行功能測試。
過關成功的樣子：學生直接雙擊 run_ai.bat，螢幕立刻彈出彩色畫面，拿起手機會被框出，按鍵盤 2 身上連起彩色人體骨架！🎉

03 工程除錯實錄：初學者四大入門障礙與底層解方

寫程式不難，難在跨越作業系統的坑。這些真實發生的阻礙是絕佳的軟體工程素養教材。

障礙一：Windows Session 0 隔離

現象：AI 在後台啟動成功，但桌面完全看不到視窗！

AI 運行的終端屬於「背景服務程序 (Daemon)」，Windows 基於資安防護，嚴禁任何背景服務將視窗投射到使用者的實體螢幕 (Session 1)。

✅ 核心解法：GUI 視窗必須由使用者在前景實體終端輸入指令，或由桌面 Shell 雙擊啟動。

障礙二：雲端硬碟 UNC 虛擬路徑

現象：雙擊批次檔，命令視窗閃退並提示不支援 UNC 路徑

專案位於 Google 雲端硬碟等虛擬掛載磁區，傳統 CMD 的 cd /d 會因為無法識別虛擬 UNC 路徑而直接中斷。

✅ 核心解法：改用 pushd "%~dp0"，Windows 會自動指派暫時虛擬代號平穩切入目錄。

障礙三：Big5 與 UTF-8 編碼衝突

現象：批次檔閃退，出現「'ho.' 不是內部或外部命令」

繁中 Windows 的 CMD 預設使用 Big5 (代碼頁 950)，以 Big5 解譯 UTF-8 的中文字元會拆解出怪異指令符號，引發語法崩潰。

✅ 核心解法：啟動用 .bat 腳本一律保持 100% 純 ASCII 英文，不得夾雜任何中文。

障礙四：GUI 初次渲染尺寸死鎖

現象：視窗順利彈出，但畫面全黑，停留在啟動中

程式判定 if lbl_w > 100: 才畫圖，但 Tkinter 標籤初次寬度為 1，因此永遠不塞圖，標籤也永遠長不大，形成競態死鎖。

✅ 核心解法：加入容錯保底機制，未量測出尺寸時預設給予 720x405 畫布直接渲染第一幀。

05 【專題製作】跨領域實戰專題發想庫

只留下市面上少見、又貼近校園與生活的題目。用一顆平價 USB WebCam 解決身邊的真實問題，做出有說服力的專題作品！

選題四個原則

  1. 從身邊的問題出發：先寫下「誰、在哪裡、遇到什麼麻煩」，再想 AI 能幫什麼。
  2. 先用現成模型試做：第一週就用預訓練模型做出能動的雛形，確認鏡頭看得到、辨識得出來。
  3. 先想好怎麼驗證：測幾次、算什麼（正確率、誤報、反應時間），這是書面報告的評分重點。
  4. 說清楚和現有產品的差別：上網查有沒有類似作品，找出更便宜、更在地或更好用的地方。

一學期進度建議

  • 第 1～2 週｜選題、查資料，用現成模型做可行性測試
  • 第 3～6 週｜收集資料（需要時訓練模型），完成第一版原型
  • 第 7～10 週｜接上燈號、語音或 ESP32，依驗證方式反覆測試並記錄數據
  • 第 11～12 週｜整理數據、拍攝展示影片
  • 第 13 週以後｜撰寫書面報告、練習上台展示

電子實習「電烙鐵無人看管」提醒

下課忘了關電烙鐵，烙鐵架長時間高溫，有起火的風險。

自動斷電線路須在老師指導下施工；不能取代正式的用電與消防安全措施。

做法
  1. 自訂模型辨識「烙鐵在架上」，再用 YOLO 預設模型偵測座位上有沒有人
  2. 座位無人超過設定時間（例如 10 分鐘）就亮燈，並語音廣播桌號
  3. 加一顆電流感測器確認烙鐵真的有通電，減少誤報
驗證方式：
模擬「人離開／回來／烙鐵沒插電」等情境各 20 次，統計漏報與誤報。
延伸方向：
比較「只用計時器」「只用電流感測」「鏡頭＋感測」三種做法，回答評審「為什麼要用鏡頭」。
專題 02・實習管理
難度：進階 ★★OpenCV 影像處理即可展示：實機⭐ 推薦起手

工具歸位「影子板」自動點檢

實習課結束常少了一把工具，一格一格清點很花時間。

做法
  1. 鏡頭固定拍攝工具掛板，先拍一張「工具全部到齊」的基準照
  2. 用 OpenCV 比對每個工具位置的畫面差異，找出空位並標上紅框
  3. 下課按一下點檢鈕，螢幕列出缺少的工具名稱
驗證方式：
隨機拿走 0～3 把工具共測 30 次，計算缺件判斷正確率，並比較不同光線的結果。
延伸方向：
進階可訓練 YOLO 辨識工具種類，判斷「放錯位置」而不只是「不見了」。
專題 03・課堂秩序
難度：進階 ★★YOLO 姿態模型可用展示：實機⭐ 推薦起手

實習課「舉手排隊」叫號

實習課同時很多人舉手，老師很難記得誰先舉手。

做法
  1. 鏡頭從教室前方拍攝全班
  2. 用 YOLO 姿態模型判斷手腕高於肩膀超過 1 秒＝舉手
  3. 依座位區域排出順序，大螢幕顯示「下一位：第 3 排」
驗證方式：
請 6～10 位同學隨機舉手測 30 輪，記錄順序正確率與漏判次數。
延伸方向：
加入「老師已處理」按鈕，統計平均等待時間。
隱私：
拍攝前先告知全班並取得同意；只顯示座位，不儲存影像。

領域二：生活安全與長照關懷

專題 04・騎士安全
難度：挑戰 ★★★YOLO 預訓練模型可用展示：錄影＋桌上模型（附練習影片）

自行車「後方來車」警示

騎單車時看不到後方大車逼近，容易被擦撞。

請用錄好的影片或模型測試，不要邊騎邊測；成品不能取代正規安全裝備。

做法
  1. 先用行車紀錄器或手機錄下騎車時的後方影片，在電腦上做辨識
  2. 偵測 car／truck／motorcycle，用框的面積變大速度估計逼近程度
  3. 桌上模型展示：亮燈、蜂鳴，語音說出「後方機車／汽車／大型車」，TFT 顯示車種與到達秒數
驗證方式：
標記每台車從旁邊經過的時間，用 evaluate.py 計算平均提早幾秒警示、漏報與誤報次數。
延伸方向：
進階可移植到手機或樹莓派，比較耗電量與反應時間。
隱私：
原始影片有車牌與路人，不上傳網路；報告與展示只用自動模糊後的標註影片。

專題 05・視障輔具
難度：挑戰 ★★★YOLO 預訓練模型可用展示：實機（封閉場地）

頭部障礙物警示帽

白手杖只探得到地面，招牌、樹枝、貨車後照鏡這類頭部高度的障礙物，視障者常常直接撞上。

只在封閉場地、有保護者陪同下測試；不能取代白手杖、導盲犬或定向行動訓練。

做法
  1. 帽簷裝兩顆 ToF 雷射測距與 USB 鏡頭，ESP32 依距離直接控制左右震動馬達
  2. 筆電放在背包裡，用 YOLO 辨識前方物體，透過骨傳導耳機說出方向、物體與距離
  3. 按下帽子上的按鈕，描述左、前、右各有什麼
驗證方式：
在包泡棉的懸掛障礙路線上，比較「只用手杖」與「手杖＋帽子」各 10 趟以上的頭部碰撞次數與完成時間。
延伸方向：
加入導盲磚方向提示，或改用樹莓派讓整套設備更輕，比較反應時間與續航。
隱私：
程式不錄影、不存照片；邀請視障者試戴前先取得同意。

專題 06・長照關懷
難度：進階 ★★OpenCV 影像處理即可展示：實機⭐ 推薦起手

長輩「藥盒打開了沒」提醒

長輩常忘記吃藥，或忘了自己已經吃過。

只作為提醒工具，不能取代醫療照護與家人確認；用藥請依醫師指示。

做法
  1. 使用分格藥盒並在每格貼上顏色標籤，鏡頭從上方拍藥盒
  2. 用 OpenCV 判斷該時段的格子有沒有被打開過
  3. 時間到還沒打開就語音提醒，並用 LINE Messaging API 通知家人（LINE Notify 已停止服務）
驗證方式：
模擬一週共 21 個用藥時段，記錄正確提醒與漏報次數。
延伸方向：
加入「同一格重複打開」提醒，避免重複吃藥。
隱私：
鏡頭只拍藥盒，不拍人。
專題 07・無障礙環境
難度：進階 ★★YOLO 預訓練模型可用展示：實機（附練習影片）⭐ 推薦起手

導盲磚「被占用」偵測

機車、腳踏車停在導盲磚上或堆放雜物，視障者走到一半就被擋住，管理單位也缺乏占用紀錄。

做法
  1. 固定鏡頭拍攝導盲磚，在畫面上點出導盲磚範圍，並調整黃色的判斷範圍
  2. YOLO 偵測機車、腳踏車，判斷輪子著地處是否在導盲磚上；黃色比例變低就代表被雜物遮住
  3. 持續占用超過設定時間就語音提醒，並記錄時間、原因與打上馬賽克的截圖，產生報表
驗證方式：
錄製晴天、陰天、傍晚的影片並標記真實占用時段，用 evaluate.py 計算召回率、精確率與誤報次數。
延伸方向：
比較有無現場提醒時的占用時間差異，或把一週報表交給總務處追蹤改善成效。
隱私：
拍攝前取得學校同意並張貼告示；截圖對行人與車牌打馬賽克，原始影片分析完就刪除。

專題 08・生活防呆
難度：入門 ★YOLO 預訓練模型可用展示：實機⭐ 推薦起手

桌面「杯子放錯位置」提醒

水杯放在鍵盤、筆電或桌緣旁，手一揮就打翻。

做法
  1. 用 YOLO 偵測 cup、bottle、keyboard、laptop
  2. 杯子離鍵盤、筆電太近，或太靠近桌緣時亮燈提醒
  3. 杯子移到安全區後才停止提醒
驗證方式：
把杯子擺在 30 個不同位置，和人工判斷的「危險／安全」比對正確率。
延伸方向：
「打翻前 0.2 秒警告」受限於鏡頭與人的反應時間做不到，所以改成事前預防；可延伸到實驗室的化學藥品瓶。
專題 09・公共安全
難度：進階 ★★YOLO 預訓練模型可用展示：實機（用剪刀練習）⭐ 推薦起手

AI 守望：公共場所「手持危險物品」通報

車站、校園發生隨機攻擊時，發現得早、通報得快是減少傷亡的關鍵，但保全不可能同時盯著每個畫面。

練習一律用剪刀代替刀械；只能連線自己的或已授權的攝影機；成品只能輔助人員判斷，不能取代保全、警察或 110。

做法
  1. YOLO 偵測人與刀、剪刀、球棒，危險物品的框和人的框重疊才算「拿在手上」
  2. 持續 0.6 秒才成立警示，嗶聲並倒數 5 秒，保全按取消鈕可取消誤報
  3. 沒人取消就截圖存證、寫入紀錄，並用 LINE Messaging API 通報；現場 ESP32 警示盒顯示燈號、倒數與取消鈕
驗證方式：
照腳本錄製校內演練影片並標記正確答案，用評估工具計算偵測率、反應秒數與每 10 分鐘誤報，再比較不同門檻的取捨。
延伸方向：
ESP32 警示盒加上語音、改用姿態模型判斷手持與倒地，或自行訓練火焰、煙霧類別。
隱私：
設置錄影告示、只用在安全用途；事件截圖定期刪除，不放進成果報告。

專題 10・品質檢驗
難度：挑戰 ★★★需自行收集照片訓練模型展示：模型

飲料杯「封膜與吸管」檢查台

飲料封膜沒封好或忘了附吸管，容易造成客訴。

做法
  1. 搭一個固定燈光與鏡頭位置的小檢查台
  2. 收集「封好／沒封／封歪」與「有無吸管」的照片，訓練自訂模型
  3. 合格亮綠燈，不合格亮紅燈並顯示原因
驗證方式：

延伸方向：
「漏液」這類瑕疵樣本很難取得，先做好「有無封膜、有無吸管」再挑戰。
