1專題概要

定位

市面上已有很多「鏡頭辨識物體再念出來」的 App 與眼鏡，所以這個專題不做完整導航，而是專注在白手杖的缺口：頭部與胸口高度的障礙物。使用者照常用白手杖探地面，帽子負責上方。

專題目標

  1. 前方 1.6 公尺內出現頭部高度障礙時，帽簷左右的震動馬達依距離與方向提醒。
  2. 障礙很近時，骨傳導耳機說出方向與是什麼（例如「右前方有人，很近，約 0.7 公尺」）。
  3. 人、腳踏車、機車快速靠近時提前提醒。
  4. 按下帽子上的按鈕，描述左、前、右各有什麼。
  5. 在安全的障礙路線中，比較「只用手杖」與「手杖＋帽子」的頭部碰撞次數。
這是輔助原型，不是正式輔具 只能在封閉場地、有保護者陪同下測試，不能取代白手杖、導盲犬或定向行動訓練，也不要讓視障者帶上街使用。

2配置與架構

分工與資料流

  1. ToF ×2量左前、右前距離
  2. ESP32立即控制兩側震動
  3. USB 線把距離與按鈕送到筆電
  4. USB 鏡頭拍攝前方
  5. 筆電 YOLO辨識人、車、椅子等
  6. 骨傳導耳機說出方向、物體與距離
為什麼震動交給 ESP32？ 步行速度約每秒 1 公尺。距離警示如果要等筆電辨識完才發出，會慢上零點幾秒；由帽子上的 ESP32 直接控制震動，筆電當機或變慢時，最基本的警示仍然有效。

6帽子組裝與背包設定

帽子

  • 元件總重控制在 200 克以內，左右對稱，戴起來不會往前傾。
  • 用熱熔膠或魔術帶固定，不要讓電路板直接碰到頭皮；背面貼絕緣膠帶。
  • ESP32 放在帽子後側或側邊，按鈕放在手容易摸到的帽簷側邊。
  • 線材不要垂在眼前或耳邊，避免勾到東西。

背包裡的筆電

  • 電源選項設定「闔上螢幕時不執行任何動作」，否則一闔上就睡眠。
  • 先執行 3_start_assist.bat，聽到「系統啟動完成」再闔上螢幕。
  • 背包要透氣，筆電直立放；每次測試後檢查是否過熱。
  • 兩條 USB 線用魔術帶沿背帶固定，接頭處留鬆弛。

8運作原理

震動（ESP32 負責）

距離震動方式程式常數
小於 0.6 公尺持續震動DIST_NEAR
0.6～1.0 公尺快速短震（每 0.2 秒一次）DIST_MID
1.0～1.6 公尺慢速短震（每 0.5 秒一次）DIST_FAR
大於 1.6 公尺或量不到不震動—

左邊的 ToF 控制左邊的馬達、右邊控制右邊，使用者可以從震動的位置知道障礙在哪一側。

語音（筆電負責）

  • 很近：任一側距離小於 near_mm（0.8 公尺）→ 說出方向；如果鏡頭在那個方向辨識到物體，就說出是什麼，例如「右前方有人，很近，約 0.7 公尺」。招牌、樹枝這類 YOLO 不認得的東西會說「障礙」。
  • 靠近：人、腳踏車、機車、汽車、狗在畫面中的面積 1 秒內變大 1.4 倍以上 →「注意，左前方有機車靠近」。
  • 按鈕：把畫面分成左、中、右三區，說出各區有什麼，以及最近的距離。
  • 不要太吵：同一種提醒至少間隔 4 秒；新的緊急提醒會取代還沒念完的舊訊息。
感測器的限制（要寫進報告） ToF 在強烈陽光下量程會變短，遇到透明玻璃、細桿子、黑色吸光材質可能量不到；YOLO 也不認得招牌、樹枝。第 3 週的材質量測表，就是要找出這些限制。

10AI 助手提示語（Antigravity／Claude Code）

用 Antigravity 開啟程式包資料夾，或在 Claude 桌面版的「Code」分頁選擇資料夾，再貼上提示語。每次修改後，都要先用 0_demo_practice.bat 確認。

① 讀懂分工
請閱讀 esp32_headgear/esp32_headgear.ino 與 headgear_assist.py，用高中生看得懂的繁體中文說明：
1. ESP32 和筆電各負責什麼？為什麼震動要放在 ESP32？
2. 兩者之間傳送的資料格式（D、B、T）
3. 語音在哪三種情況會說話？如何避免一直講話？
先不要修改任何檔案。
② 調整震動距離
我們的受測者覺得 1.6 公尺就開始震動太早了。請把 esp32_headgear.ino 的 DIST_FAR 改成 1300、DIST_MID 改成 900，
並在程式註解說明這三個門檻的意義。改完告訴我怎麼用 Arduino IDE 重新上傳，不要幫我上傳。
③ 分析誤報
請讀取 logs 資料夾中最新的 CSV，統計每種提醒（near、approach、button、sensor_lost）的次數，
列出 near 提醒時的左右距離分布，並找出「兩次提醒間隔很短」的時段。
根據結果建議 near_mm、repeat_cooldown_sec、approach_ratio 要怎麼調整。先不要修改程式。
④ 延伸：導盲磚方向提示
請在 headgear_assist.py 新增「導盲磚模式」：在 config.json 加入 tactile_mode（預設 false）。
開啟時，分析畫面下方 1/3 的黃色區域（HSV 色相 18～35），黃色重心偏左超過畫面寬度 15% 就說「導盲磚在左邊」，
偏右就說「導盲磚在右邊」，同一句話至少間隔 5 秒。
改完請用 make_demo_video.py 產生的影片執行 --no-voice 測試，確認原本的功能沒有壞掉再回報。
⑤ 整理實驗結果
請執行 python evaluate_trials.py，讀取 trials.csv，並把結果整理成書面報告可用的表格與一段 150 字的分析，
說明頭部碰撞、完成時間、誤報的變化，以及趟數是否足夠、可能的誤差來源。數字只能用 trials.csv 裡的資料。

11測試與驗證

障礙路線

  • 在走廊或空教室規劃 10～15 公尺的直線路線，地面平坦，不要有樓梯。
  • 用繩子懸掛 3～5 個包泡棉的紙箱，高度 1.4～1.8 公尺（頭部與胸口）；地面放 2 個泡棉塊。
  • 每一趟隨機改變障礙位置，避免受測者記住路線。
  • 受測者戴眼罩、拿白手杖，保護者全程走在旁邊，喊「停」就立刻停下。

比較實驗

  • 每位受測者「只用手杖」與「手杖＋帽子」各走至少 10 趟，兩種模式輪流交換順序。
  • 每趟記錄到 trials.csv：完成秒數、頭部碰撞、地面碰撞、警示次數、誤報次數。
  • 執行 4_evaluate_trials.bat 比較兩種模式。

感測器測試

測試方法記錄
警示距離慢慢走向懸掛紙箱，用捲尺量第一次震動時的距離每種材質 10 次的平均與誤差
材質紙箱、黑布、透明塑膠板、細竿（直徑 2 公分）、樹葉能否量到、量到的最遠距離
環境室內、窗邊、戶外陰影、陽光下量程變化
反應時間用手機慢動作錄影，數「障礙出現」到「震動」的影格數平均延遲（毫秒）
語音比對 logs/ 與錄影，檢查說的方向與物體是否正確正確率、誤報次數

12安全、隱私與倫理

  • 所有測試都在封閉場地進行，有老師在場，保護者全程陪同。
  • 懸掛障礙物一律包泡棉；路線上沒有樓梯、尖角、玻璃。
  • 受測者有身體不適、頭暈就立刻停止；戴眼罩前先確認路線與停止口令。
  • 只使用 3.3V 低壓元件，電路板背面絕緣，避免接觸皮膚。
  • 筆電在背包中要注意散熱，使用後檢查溫度。
  • 程式不錄影、不存照片；拍攝成果影片要先取得入鏡者同意。
  • 邀請視障者試戴前先說明用途與風險並取得同意，報告中不寫出可辨識身分的資料。
  • 報告與展示時清楚說明：這是輔助原型，不能取代白手杖、導盲犬或定向行動訓練。

14第二版：改用樹莓派（選做）

第一版穩定後，可以把筆電換成樹莓派，讓整套設備更輕。

  • 硬體：Raspberry Pi 5（8 GB）、Camera Module 3 Wide、AI 加速板（如 Raspberry Pi AI HAT+）、行動電源、散熱外殼，約再增加 5,000～8,000 元。
  • 電源：樹莓派 5 官方建議 5V 5A 電源；一般行動電源輸出較低，USB 周邊可用電流會受限制，要實測能不能穩定運作。
  • 要比較的項目：辨識速度（FPS）、反應時間、續航時間、重量、溫度，和第一版做成對照表。

15書面報告與評分

報告架構

  1. 摘要：問題、方法、比較實驗的主要結果（用自己測到的數字）。
  2. 研究動機：白手杖的限制、訪談內容。
  3. 文獻與現況：現有電子手杖、智慧眼鏡、辨識 App，說明本作品專注在頭部高度的差別。
  4. 研究方法：配置圖、接線、震動與語音設計、參數。
  5. 測試與結果：感測器限制、障礙路線比較、誤報分析、改良前後比較。
  6. 討論：限制、安全措施、專家回饋。
  7. 結論與未來展望：例如第二版樹莓派、導盲磚模式。
