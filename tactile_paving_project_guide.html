導盲磚占用偵測：
用一顆鏡頭守護視障者的路

機車、腳踏車停在導盲磚上，或堆放雜物，視障者走到一半就會被擋住。這個專題用 USB 網路攝影機加上 AI 影像辨識，偵測導盲磚是否被占用，持續占用時發出提醒並留下紀錄，協助管理單位改善。

1專題概要

要解決的問題

導盲磚是視障者行走的重要依據，但常被停放的機車、腳踏車或店家的招牌、紙箱擋住。巡查人員不可能隨時在現場，被占用的地點與時段也缺乏紀錄。

專題目標

  1. 即時偵測導盲磚上的車輛與雜物，行人經過不誤報。
  2. 持續占用超過設定時間，現場語音提醒（選配：警示燈、LINE 通知）。
  3. 自動記錄每次占用的時間、原因與打上馬賽克的截圖，產生報表給管理單位。
  4. 用實際影片驗證準確率，提出改善建議。
這個題目的特色 系統幫助的是「維護導盲設施的人」，不需要讓視障者冒險測試原型；而且除了 YOLO 認得的車輛，還用黃色比例抓出 YOLO 不認得的雜物，是和一般物件偵測專題不同的地方。

完成後的樣子

  • 電腦畫面顯示導盲磚區域：綠色＝淨空、橘色＝疑似占用（計時中）、紅色＝警示。
  • 喇叭播放「此處為導盲磚，請勿停放車輛或堆放物品」。
  • output/report.html 報表：事件數、占用總時間、原因統計、各時段分布、事件明細。

2系統架構

  1. USB 攝影機拍攝導盲磚
  2. OpenCV讀取畫面、套用導盲磚區域
  3. YOLO11偵測機車、腳踏車等
  4. 黃色比例判斷是否被雜物遮住
  5. 占用判斷車輛著地處或遮擋
  6. 持續計時超過 N 秒才警示
  7. 提醒與紀錄語音、截圖、CSV
  8. 報表與驗證統計、準確率

輸入

  • 即時攝影機畫面，或預先錄好的影片
  • config.json：導盲磚區域、黃色範圍、秒數門檻

輸出

  • 即時畫面與語音提醒（選配 ESP32 警示燈、LINE 通知）
  • output/events.csv、state_log.csv、snapshots/、report.html

5場地與鏡頭架設

選擇場地

  • 先在校內或校門口找有導盲磚、常被停車的地點，拍照記錄現況。
  • 向學校（總務處、學務處）說明專題目的，取得拍攝同意。
  • 現場張貼「本區域進行學生專題攝影，影像僅供研究並打馬賽克處理」告示。

鏡頭位置

  • 高度約 2.5～4 公尺，往下斜拍，完整拍到一段導盲磚。
  • 避免正對太陽或路燈（逆光會讓黃色判斷失準）。
  • 固定牢靠，鏡頭一移動就要重新設定區域。
  • 線材沿牆固定，不要橫跨通道。

要錄的測試影片

每支 5～10 分鐘，至少錄下列情境各一次，之後用來調整參數與計算準確率：

  • 白天晴天、陰天、傍晚（光線變暗）
  • 機車停放、腳踏車停放、紙箱或招牌遮擋
  • 行人、腳踏車只是「經過」（不應警示）
  • 有樹影或建築陰影落在導盲磚上

7核心判斷方法

訊號一：車輛停在導盲磚上

YOLO 會框出機車、腳踏車等物件。但車身在畫面上會「浮」在導盲磚上方（透視關係），所以只取框的下方 35%（輪子著地的位置），計算這一塊有多少比例落在導盲磚區域內，超過 overlap_threshold（預設 0.3）就算車輛占用。

訊號二：導盲磚被雜物遮住

YOLO 不認得紙箱、招牌、盆栽。改用顏色判斷：把畫面轉成 HSV 色彩空間，計算導盲磚區域裡「黃色像素」的比例。淨空時的比例當作基準值，當比例低於基準值的 blocked_ratio（預設 5 成），就算被遮住。

持續計時，避免誤報

行人或車輛只是經過時，也會短暫擋住導盲磚。所以「被占用」必須連續超過 occupy_seconds 秒才發出警示；淨空超過 clear_seconds 秒才算事件結束。

每張畫面：
  黃色比例 = 導盲磚區域內黃色像素數 ÷ 區域像素數
  車輛重疊 = 各車輛框下方 35% 落在區域內的最大比例

  被占用 = (車輛重疊 ≥ 0.3) 或 (黃色比例 < 基準值 × 0.5)

  如果 被占用：
      若尚未開始計時 → 記下開始時間
      若已持續 ≥ occupy_seconds 且尚未警示 → 發出警示、截圖、記錄
  否則：
      若已淨空 ≥ clear_seconds → 事件結束，寫入 events.csv，重設
為什麼不每張畫面都跑 YOLO？ 筆電 CPU 跑 YOLO 比較慢。導盲磚占用是「慢慢發生」的事件，程式每 0.5 秒偵測一次（detect_interval_sec）就夠用，可以大幅降低 CPU 負擔。

8程式包使用說明

檔案用途

實際場地的操作順序

  1. 把 config.json 的 source 改成攝影機編號（外接鏡頭常是 1）。
  2. 雙擊 1_setup_roi.bat，點出導盲磚範圍。
  3. 導盲磚淨空時，雙擊 2_tune_color.bat，調到遮罩視窗裡導盲磚是白色、其他地方是黑色，按 s。
  4. 實際場地把 occupy_seconds 改成 180（3 分鐘）左右，雙擊 3_run_monitor.bat。
  5. 結束後雙擊 4_make_report.bat，打開 output/report.html。

計算準確率

1. 把 config.json 的 source 改成測試影片檔名，例如 "site_day1.mp4"
2. 看影片，把真正被占用的時段填進 ground_truth.csv（單位：秒）
      start_sec,end_sec,note
      125,410,機車停放
3. python paving_monitor.py --no-window
4. python evaluate.py --min-event 30        （數字要和 occupy_seconds 一樣）

練習影片的參考結果：兩個占用事件都有抓到，行人經過沒有誤報，逐秒 F1 約 95%。

11隱私、安全與倫理

  • 拍攝前取得學校同意，現場張貼告示。
  • 截圖一律打馬賽克（blur_privacy 保持 true），不公開車牌與人臉。
  • 原始影片只保存到分析完成，之後刪除；不上傳到公開網站或社群。
  • 紀錄只用於改善導盲設施，不作為檢舉、公布個人的用途；要提供給管理單位前，先經老師確認。
  • 訪談視障者或相關人士前先說明用途並取得同意，報告中不寫出可辨識身分的資料。
  • 鏡頭、腳架、延長線不擋住通道，不在車道或危險位置架設。
  • ESP32 只使用低壓元件，不接市電。
  • 系統只是輔助提醒，不能取代巡查與實體的無障礙設施維護。

行人停下來聊天就警示黃色被人擋住超過設定秒數把 occupy_seconds 調長；或在程式中排除有 person 的時段
沒有語音電腦沒有中文語音或沒裝 pyttsx3到 Windows「語音」設定新增中文語音；程式會改用嗶聲
畫面很卡電腦效能不足把 detect_interval_sec 改成 1；降低攝影機解析度

13延伸方向

  • 夜間偵測：加裝補光燈，或比較紅外線鏡頭的效果。
  • 多點監測：同時接兩顆鏡頭，比較不同地點的占用熱點。
  • 自訂模型：拍攝招牌、盆栽、機車停車架的照片訓練 YOLO，讓「原因」分得更細。
  • 現場互動：用 ESP32 控制「請勿停車」警示燈，比較有提醒與沒提醒時的占用時間差異。
  • 邊緣部署：移植到樹莓派，比較耗電量、反應時間與準確率。
  • 與學校合作：把一週的報表交給總務處，追蹤改善前後的變化。

14書面報告架構

  1. 摘要：問題、方法、最重要的測試結果（用實際數字）。
  2. 研究動機：現場照片、訪談內容、為什麼需要自動偵測。
  3. 文獻與現況：導盲磚規範、現有巡查方式、類似的影像辨識系統，說明本作品的不同。
  4. 研究方法：系統架構、硬體、判斷方法、參數設定。
  5. 測試與結果：影片數量與時長、情境矩陣、準確率、誤報與漏報分析、改良前後比較。
  6. 討論：限制（夜間、角度、遮擋一半）、隱私保護做法。
  7. 結論與未來展望。
  8. 參考資料與附錄：程式、設定檔、訪談同意書範本。
數據一定要是自己測的 報告中的所有數字都要來自自己的影片與 evaluate.py 的結果，並保留原始紀錄檔，評審可能會要求查看。
